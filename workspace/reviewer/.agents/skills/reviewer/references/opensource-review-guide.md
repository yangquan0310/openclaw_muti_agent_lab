# 开源论文审稿指南

> 适用于：arXiv 预印本、技术报告、开源项目文档、研究笔记等

---

## 开源论文特殊性

| 维度 | 开源论文特点 | 审稿重点 |
|------|--------------|----------|
| **发表形式** | 无正式同行评审 | 社区评审/自我声明 |
| **时效性** | 快速发布，抢占优先权 | 数据和方法的时效性 |
| **可重复性** | 强调代码开源 | 代码和数据是否可用 |
| **受众** | 技术人员为主 | 可理解性和可复现性 |

---

## 额外审查维度

### 9. 开源论文专项审查

#### 9.1 可复现性
- 代码是否开源可用
- 数据集是否公开或说明获取方式
- 运行环境是否明确
- 实验参数是否完整记录

#### 9.2 技术严谨性
- 数学推导是否正确
- 算法描述是否完整
- 实现细节是否充分

#### 9.3 社区适用性
- 是否适合目标社区（arXiv/cs.LG/cs.CL/cs.CV等）
- 代码质量是否达到开源标准
- 依赖是否合理

#### 9.4 版本声明
- 是否明确说明这是预印本
- 是否标注版本历史
- 是否有更新声明

## 开源论文常见问题

### 🔴 critical（核心问题）

1. **代码不可用或无法复现**
   - 问题：声称开源但代码缺失/不完整/无法运行
   - 建议：补充代码或说明障碍

2. **方法描述严重缺失**
   - 问题：关键算法/模型描述不完整
   - 建议：补充技术细节

3. **结果数据与代码不符**
   - 问题：声称的结果无法复现
   - 建议：核实数据或更正声称

### 🟡 major（重要改进）

1. **数学推导存在错误**
2. **实验设置描述不完整**
3. **数据集描述不够详细**
4. **Related Work 不全面**

### 🟢 minor（细节优化）

1. **论文结构可以更清晰**
2. **部分技术细节可以补充**
3. **格式规范化**

## arXiv 专项检查

| 检查项 | 说明 | 优先级 |
|--------|------|--------|
| 分类是否正确 | 是否选择了合适的 arXiv 分类 | 🔴 |
| 标题是否准确 | 是否反映论文核心贡献 | 🟡 |
| 摘要是否完整 | 是否包含方法+结果+贡献 | 🟡 |
| 作者信息 | 联系方式是否正确 | 🟢 |
| 引用格式 | 是否标注预印本状态 | 🟢 |

---

## 开源项目 README 检查

对于附有开源项目的论文：

- [ ] README 是否清晰说明项目用途
- [ ] 安装说明是否完整
- [ ] 使用示例是否可用
- [ ] 许可证是否标注
- [ ] 贡献指南是否提供
- [ ] 变更日志是否记录
