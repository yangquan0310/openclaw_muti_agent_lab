# reviewer 使用指南

> 通用审稿方法论，适用于所有类型的学术文稿审稿。

---

## 审稿流程

### 第一步：快速定位论文类型

```
论文类型判断：
├── 字数 > 3万字 → 可能是学位论文
├── 有期刊名称/卷期页码 → 期刊论文
├── arXiv/预印本标识 → 开源论文
├── 课程名称/学期标识 → 课程论文
└── 项目名称/课题编号 → 项目申请书
```

### 第二步：选择对应指南

根据论文类型选择专用指南（见 index.md），结合本通用指南审稿。

### 第三步：结构化审查

按八大维度逐项检查：
1. 选题的重要性
2. 文献综述质量
3. 问题提出
4. 研究方法
5. 数据分析和结果
6. 讨论和结论
7. 文稿呈现
8. 研究贡献

### 第四步：输出审稿意见

使用 SKILL.md 中的输出模板，保持：
- 先肯定优点，再指出问题
- 具体问题位置 + 改进建议
- 按优先级排序

---

## 审稿态度指南

| 态度 | 做法 | 避免 |
|------|------|------|
| 建设性 | 指出问题后给出改进建议 | 只说"不好"而不说"怎么改好" |
| 尊重 | 评论论文而非作者 | 评价作者能力或态度 |
| 协作 | 假设作者希望做好研究 | 预设作者"偷懒"或"故意" |
| 聚焦 | 只提与论文质量相关的问题 | 吹毛求疵或提出超出范围的要求 |
| 平衡 | 既指出不足也肯定优点 | 只批评不肯定 |

## 改进用语对照表

| 避免使用（指责性） | 建议使用（建设性） |
|-------------------|-------------------|
| "作者显然不理解..." | "这一部分可以考虑澄清..." |
| "这是一个严重错误" | "修正这一点能让结论更可靠" |
| "文献综述很差" | "补充以下几篇文献能让综述更完整..." |
| "统计分析有问题" | "建议使用XX方法，因为..." |
| "写作质量低" | "以下调整能提升可读性..." |
| "没有创新性" | "可以考虑从XX角度进一步挖掘新意" |

---

## 注意事项

1. **审稿即改进**：审稿的本质是帮助论文变得更好
2. **先扬后抑**：先指出亮点，再提出改进建议
3. **只说问题不说人**：仅针对论文内容
4. **建议要具体**：避免笼统批评
5. **区分事实与偏好**：区分科学不严谨和个人偏好
6. **聚焦可改进项**：不提出论文框架无法容纳的要求
