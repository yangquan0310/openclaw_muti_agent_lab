# 修改方法论

> 修改文章的标准工作流

---

## 核心工作流

```
建立论证地图 → 创建修改清单 → 汇报确认 → 逐章执行 → 终极核查
```

**任何修改前必须先汇报计划并等待确认。**

---

## 步骤一：建立论证地图

### 操作

1. 用一句话提炼**核心命题**
2. 绘制**论证链**（若干逻辑环节的递进关系）
3. 标注**每章在链中的位置**

### 输出格式

```
核心命题：[一句话概括]

论证链：
  环节1 → 环节2 → 环节3 → ... → 核心命题

章节定位：
  - 第X章：论证环节X
  - 第Y章：论证环节Y
  ...
```

---

## 步骤二：创建修改清单

### 组织层级

| 层级 | 内容 | 优先级 |
|------|------|--------|
| **全局修改** | 术语统一、格式规范 | P0-P1 |
| **章节修改** | 逻辑结构、论证深度 | P2-P4 |
| **实验/证据章修改** | 数据报告、方法描述 | P2-P4 |
| **跨章一致性** | 前后一致、闭环检验 | P3-P5 |

### 优先级定义

| 优先级 | 定义 |
|--------|------|
| P0 | 术语清洗 |
| P1 | 引用修复 |
| P2 | 图表编号 |
| P3 | 作者名空缺 |
| P4 | 逻辑深度 |
| P5 | 段落结构 |
| P6 | 终极核查 |

---

## 步骤三：论证中心检验

### 规则

**每条修改建议必须能定位到论证链的某一环。**

### 自检

逐条问："此修改服务于论证链的哪一环？"
- 如果无法清晰定位 → 冗余，应删除
- 如果能定位 → 保留

### 背景层 vs 核心层

| 类型 | 说明 |
|------|------|
| **核心层** | 直接服务于核心命题的论证链 |
| **背景层** | 精确边界描述，属于间接服务 |

---

## 步骤四：汇报确认

### 规则

**必须先汇报计划，等用户确认后再执行。**

### 汇报内容

1. 论证地图（步骤一）
2. 修改清单（步骤二）
3. 每条修改的定位（步骤三）
4. 执行顺序

---

## 步骤五：逐章执行

### 顺序

按优先级从高到低执行：
P0 → P1 → P2 → P3 → P4 → P5 → P6

### 自检

每章修改后：
- 是否解决了该优先级的问题？
- 是否引入了新问题？

---

## 步骤六：终极核查

### 核查维度

| 维度 | 检查项 |
|------|--------|
| **术语** | 全篇统一，无同义词混用 |
| **引用** | 格式统一，无占位符 |
| **结构** | 论证闭环，逻辑连贯 |
| **证据** | 三层区分清晰，无空推 |

---

## 本章小结

1. **论证地图**：核心命题 → 论证链 → 章节定位
2. **修改清单**：按层级组织（P0-P6）
3. **论证中心检验**：无法定位 → 冗余
4. **汇报确认**：必须先汇报，等确认后再执行
5. **逐章执行**：按优先级执行
6. **终极核查**：六维度检查
