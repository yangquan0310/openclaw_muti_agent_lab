# PPT 脚本编写指南

> **目标**：让任何人都能按照规范编写出可直接编译为 PPT 的演示文稿脚本。
>
> **适用范围**：任何需要通过结构化脚本自动生成 PPT 的场景（教学课件、工作汇报、产品演示等）。
>
> **格式版本**：v2.2（支持元数据 + 多主题 + 新结构类型）

---

## 一、脚本是什么

PPT 脚本是一个 `.md` 文件，用**结构化标记**描述每一页幻灯片的内容和呈现方式。

编译器读取脚本 → 按标记提取信息 → 自动匹配 Layout → 生成 `.pptx`。

---

## 二、YAML 元数据头（可选）

脚本开头可包含 YAML front matter，定义文档级属性：

```markdown
---
title: 演示文稿标题
author: 作者名
date: 2026-05-21
theme: blue  # 可选：blue/green/purple/orange/gray
---

# 演示文稿标题
```

| 字段 | 说明 |
|------|------|
| title | 文档标题（用于编译输出） |
| author | 作者 |
| date | 日期 |
| theme | 配色主题（覆盖命令行 --theme） |

---

## 三、脚本的整体结构

```markdown
# 演示文稿标题（可选）

---

## 第1页：页面标题

@structure: cover

**页面描述**：...
**核心内容**：
- ...
**图表设计**：...
**备注**：...

---

## 第2页：页面标题

@structure: list
@layout: 1

**核心内容**：
- ...
**图表设计**：...
**备注**：...
```

### 每个脚本包含

| 组成部分 | 数量 | 说明 |
|----------|------|------|
| `# 演示文稿标题` | 1个 | 文件顶部，标识主题 |
| `---` | 若干 | 页面之间的分隔线 |
| `## 第N页` | 多个 | 每个幻灯片一页 |
| `@structure` | 每页可选 | 声明内容结构类型，编译器自动匹配 Layout |
| `@layout` | 每页可选 | 强制覆盖 Layout 索引 |
| 信息块（4~5种） | 每页 | 每页必须有 `核心内容` |

---

## 三、快捷标记（页面顶部）

### @structure — 内容结构类型

声明页面内容的逻辑结构，编译器自动选择最合适的 Layout。

```markdown
## 第1页：封面

@structure: cover
```

| @structure | 内容类型 | 自动匹配 Layout | 索引 | 内容特征关键词 |
|------------|----------|-----------------|------|----------------|
| `@cover` | 封面 | 标题幻灯片 | 0 | 标题、副标题、作者/日期 |
| `@list` | 列表（最常用） | 标题和内容 | 1 | 要点、条目、①②③ |
| `@section` | 章节分隔 | 节标题 | 2 | PART、第一节、过渡 |
| `@compare` | 双栏对比 | 两栏内容 | 3 | vs、对比、比较、异同 |
| `@table` | 表格 | 标题和内容 | 1 | 表格、统计、数据、百分比 |
| `@timeline` | 时间轴 | 标题和内容 | 1 | 世纪、年代、起源、演变 |
| `@flowchart` | 流程图 | 标题和内容 | 1 | 步骤、流程、程序、①→② |
| `@cards` | 卡片网格 | 标题和内容 | 1 | 分类、类型、特点、五大 |
| `@toc` | 目录 | 标题和内容 | 1 | 目录、章节列表、导航 |
| `@quote` | 引用/金句 | 标题和内容 | 1 | 名言、金句、语录 |
| `@stats` | 统计数字 | 标题和内容 | 1 | 数据、百分比、关键指标 |

> `@table`/`@timeline`/`@flowchart`/`@cards`/`@toc`/`@quote`/`@stats` 使用 Layout 1（标题和内容），编译器会自动在 slide 上设计对应的呈现方式。

### @layout — 强制指定 Layout

当自动推断不满足需求时，显式覆盖：

```markdown
## 第3页：导入

@structure: compare
@layout: 3
```

**优先级**：`@layout` 显式指定 > `@structure` 推断 > 默认 `@list`

### 常见 Layout 选择表

| 内容类型 | Layout 名称 | 索引 |
|----------|-------------|------|
| 封面 | 标题幻灯片 | 0 |
| 正文/知识点 | 标题和内容 | 1 |
| PART/第一节 | 节标题 | 2 |
| vs/双栏对比 | 两栏内容 | 3 |
| 多栏对比 | 比较 | 4 |
| 思考题/讨论 | 仅标题 | 5 |
| 左内容右标题 | 内容与标题 | 6 |
| 带图片正文 | 图片与标题 | 7 |

> 查看全部：`python3 scripts/main.py list --template template`

## 四、每个信息块写入什么

### 4.1 页面描述

**写什么**：这一页的功能定位——这页是干什么的，观众看完应该获得什么。

**示例**：
```markdown
**页面描述**：展示项目三个核心目标，引导观众关注重点
**页面描述**：时间轴展示公司发展历程
**页面描述**：用卡片分类展示产品的五大特点
```

**不写什么**：
- ❌ 不要写"这是第2页"
- ❌ 不要写重复信息

---

### 4.2 核心内容（必需）

**写什么**：这一页上要展示的所有文字内容。

**格式规则**：
1. 第1行 → 页面大标题
2. 第2行起 → 内容条目
3. 支持 Markdown 列表（`- ` 或 `1. `），编译时自动去掉前缀
4. 空行会被跳过

**示例**：
```markdown
**核心内容**：
- 一、公司发展历程
- 2018年：产品原型诞生
- 2020年：获得A轮融资
- 2022年：用户突破百万
- 2024年：全球化布局启动
```

**标题 vs 内容的区分**：
```markdown
**核心内容**：
- 项目核心目标              ← 标题
- 提升用户体验30%          ← 内容1
- 降低运营成本20%          ← 内容2
- 开拓三个新市场           ← 内容3
```

**不写什么**：
- ❌ 不要写图表说明（如"三个圆圈编号①②③"——这是 `图表设计` 的内容）
- ❌ 不要写备注（如"时间控制2分钟"——这是 `备注` 的内容）

---

### 4.3 图表设计

**写什么**：这一页的视觉呈现方式——形状、排列、特殊元素。

**写什么不写什么的界限**：

| 应该写 | 不应该写 |
|--------|----------|
| "三个圆圈编号①②③" | "用蓝色背景"（颜色由模板决定） |
| "水平时间轴，4个节点" | "字体用Arial"（字体由模板决定） |
| "2×2卡片网格" | "动画效果：淡入"（编译器不支持动画） |
| "左侧标题，右侧图片" | "图片从百度下载"（图片由模板自带） |

**示例**：
```markdown
**图表设计**：
- 三个圆圈编号（①②③），每个目标对应一个圆圈
- 时间轴布局：水平线+4个圆形节点
- 5个卡片，2+3排列，每个卡片包含标题和描述
- 左侧：概念定义，右侧：示例说明
```

**不写什么**：
- ❌ 颜色、字体、字号（模板统一控制）
- ❌ 动画、切换效果（编译器不支持）
- ❌ 图片来源、下载方式

---

### 4.4 互动设计（可选）

**写什么**：这一页的演示互动环节——提问、讨论、活动。

**示例**：
```markdown
**互动设计**：
- 提问："大家觉得这三个目标中，哪个最具挑战性？"
- 小组讨论：5分钟讨论，每组选一个代表发言
- 现场投票：举手表决
```

**如果无互动**：
```markdown
**互动设计**：无
```

> 注：`互动设计` 为可选信息块。非演示场景（如工作汇报）可省略。

---

### 4.5 备注

**写什么**：给演讲者的提示——时间控制、重点强调、注意事项。

**示例**：
```markdown
**备注**：
- 时间控制：2分钟
- 重点强调：第三个目标最容易被忽略
- 注意事项：提前准备投票器
```

**如果无备注**：
```markdown
**备注**：无
```

## 五、编写原则

### 5.1 一页只说一件事

```markdown
## 第4页：发展历程     ✅ 聚焦：历史演变
## 第5页：五大特点     ✅ 聚焦：特征归纳
## 第6页：历程+特点+思考  ❌ 三件事塞在一页
```

### 5.2 内容密度适中

- 一页 **3~6个内容条目** 为最佳
- 超过8条 → 考虑拆分为两页
- 只有1条 → 考虑加案例或图表丰富化

### 5.3 标题要概括，内容要具体

```markdown
✅ 好的例子：
- 产品的五大特点          ← 标题：概括
- 高性能：响应速度提升3倍   ← 内容1：具体
- 易用性：三步完成操作      ← 内容2：具体

❌ 不好的例子：
- 产品特点                ← 太笼统，没有信息量
- 特点1                   ← 无意义编号
- 特点2                   ← 无意义编号
```

### 5.4 信息块各司其职

| 信息块 | 职责 | 常见错误 |
|--------|------|----------|
| 页面描述 | 功能定位 | 写成内容摘要 |
| 核心内容 | 展示文字 | 混入图表说明 |
| 图表设计 | 视觉方式 | 写成内容文字 |
| 互动设计 | 演示活动 | 写成演讲者讲解 |
| 备注 | 演讲提示 | 写成观众提示 |

## 六、完整示例

```markdown
# 产品发布会

---

## 第1页：封面

@structure: cover

**页面描述**：发布会封面，展示产品名称、公司、日期

**核心内容**：
- 智云办公 3.0
- 新一代智能协作平台
- 智云科技
- 2026年5月

**图表设计**：
- 左上角：公司 Logo
- 右侧：产品界面截图

**备注**：无

---

## 第2页：核心目标

@structure: list

**页面描述**：展示产品三个核心目标，引导观众关注重点

**核心内容**：
- 产品核心目标
- 提升团队协作效率 30%
- 降低沟通成本 50%
- 支持全球化远程办公

**图表设计**：
- 三个圆圈编号（①②③），每个目标对应一个圆圈

**互动设计**：
- 提问："大家觉得这三个目标中，哪个最具挑战性？"

**备注**：时间控制 2 分钟

---

## 第3页：发展历程

@structure: timeline

**页面描述**：时间轴展示产品迭代历程

**核心内容**：
- 一、产品发展历程
- 2022年：智云办公 1.0 发布
- 2023年：引入AI智能助手
- 2024年：用户突破百万
- 2025年：企业版上线
- 2026年：智云办公 3.0 全新发布

**图表设计**：
- 水平时间轴，5 个时间节点
- 节点样式：圆形 + 年份标签

**备注**：每个时间点讲解 1 分钟

---

## 第4页：感谢

@structure: cover

**页面描述**：结束页，展示感谢信息和联系方式

**核心内容**：
- 感谢聆听
- 智云科技
- www.zhiyun.com
- contact@zhiyun.com

**图表设计**：
- 简洁背景，居中大字

**备注**：无
```

## 七、常见问题

### Q1：不知道选哪个 @structure 怎么办？

参考上面的"@structure 与 Layout 映射表"。最常用的是 `@list`，不确定就用它。

### Q2：内容太多一页放不下怎么办？

拆分为两页：
```markdown
## 第5页：五大特点（上）
@structure: list
**核心内容**：
- 二、产品的五大特点
- 高性能：响应速度提升3倍
- 易用性：三步完成操作

---

## 第6页：五大特点（下）
@structure: list
**核心内容**：
- 安全性：银行级加密标准
- 可扩展：支持百万级并发
- 智能化：AI 自动优化工作流
```

### Q3：图表设计不会写怎么办？

如果不会写，就写：
```markdown
**图表设计**：无
```

编译器会使用 layout 的默认样式。

### Q4：互动设计想不出来怎么办？

如果这一页不需要互动，就写：
```markdown
**互动设计**：无
```

不要硬凑互动。

## 八、检查清单

写完脚本后，逐页检查：

- [ ] 每页都有 `**核心内容**：`（至少2行）
- [ ] 核心内容第1行是标题，后面是具体内容
- [ ] 内容密度适中（3~6条）
- [ ] 信息块各司其职，没有串位
- [ ] 页面之间用 `---` 分隔
- [ ] @structure 标记正确（如有使用）

## 九、与具体项目的结合

本指南是**通用规范**。在具体项目中使用时：

1. **确定输出路径**：根据项目规范确定 `.md` 脚本的存放位置
2. **确定编译方式**：调用项目指定的编译工具生成 `.pptx`
3. **遵循项目额外约束**：如特定术语、格式要求、审核流程等

> 例如，在课程备课项目中，脚本可能需遵循额外的 `v4 课件脚本` 规范（包含教学互动设计、时间控制等）。项目级规范应补充到项目的操作手册中，而非修改本通用指南。
