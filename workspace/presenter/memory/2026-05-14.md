## 下午：修复颜色风格和内容错位

### 问题诊断
用户反馈两大问题：
1. **颜色风格错误**：生成了深色PPT（深棕背景+白字），但要求浅色（白背景+黑字）
2. **内容错位**：预定位文本框填充顺序与内容顺序不匹配

### 颜色修复
- 新增 `course_presenter/color_transform.py` — 自动转换深色→浅色
- 转换规则：
  - 深棕色背景 → 移除（恢复白色）
  - 白色文字(#FFFFFF) → 黑色(#000000)
  - 金黄色(#FFD700) → 深蓝(#113556)
  - 深橙装饰(#2D1B0E/#E67300) → 浅橙(#FFF3E0/#FFF8E1)
- 生成 `template_light.pptx` 浅色母版模板

### 内容错位修复
根本原因：预定位文本框按位置排序后，填充顺序与内容语义不匹配

**示例：cards_5布局**
- 文本框顺序：[标题, 标题1, 标题2, 标题3, 描述1, 描述2, 描述3, 标题4, 标题5, 描述4, 描述5, 口诀]
- 原填充：[标题, 标题1, 描述1, 标题2, 描述2...] ← 错误！描述1填入标题2的位置
- 修复后：按上下排分组填充

**新增 renderer_v3.py 修复：**
1. 排除页脚位置文本框（y > 6.5 inches）
2. 按布局类型智能映射内容：
   - `_render_timeline()` — 时间轴：上排时间点+下排描述分离
   - `_render_cards()` — 卡片：标题+描述按位置分组
   - `_render_steps()` — 步骤：顺序填充
   - `_render_list()` — 列表：顺序填充
   - `_render_dual()` — 左右对比：顺序填充
   - `_render_table()` — 表格：过滤表格行填充
3. 脚本解析器过滤图表说明文字（"时间轴主线"、"五个特点用卡片"等）
4. 修复页脚重复添加问题

### 验证结果
- 第5页（起源与发展）✓：4个时间点+4个描述，无重复
- 第6页（五大特点）✓：标题→卡片标题→卡片描述顺序正确
- 输出：`课件_v4.1_light_v8.pptx`（已上传飞书）

### 最新关键文件
- `course_presenter/color_transform.py` — 颜色转换器
- `course_presenter/renderer_v3.py` — 修复版渲染器

## 晚上：course-presenter v5.0 重构

### 架构重构：母版克隆 → 标准 slide_layouts + placeholders

**问题**：v4.0 母版克隆方式丢失占位符结构，新增slide时形状位置错乱，无法利用python-pptx标准API。

**解决方案**：基于 python-pptx 标准 `slide_layouts` + `placeholders` 模式

### 核心组件

| 文件 | 功能 |
|------|------|
| `scripts/TemplateExtractor.py` | 从武汉文理模板提取为标准模板（白色背景#FFFFFF、标题32pt、正文28pt、Times New Roman/微软雅黑） |
| `scripts/PptxCompiler.py` | 混合编译器：标准layout（索引<N，占位符填充）+ 原型slide（索引≥N，克隆+文本替换） |
| `scripts/TemplateExtender.py` | 添加自定义layout原型（timeline/flowchart/cards/table），添加到模板末尾作为原型slides |
| `scripts/ScriptParser.py` | 丰富模式脚本解析器，支持 `**页面描述**`、`**母版布局**`、`**核心内容**`、`**图表设计**`、`**互动设计**`、`**备注**` |
| `scripts/main.py` | CLI统一入口（list / extend / compile / parse） |

### LayoutAdvisor 被删除

用户明确要求："删除LayoutAdvisor.py，不要使用脚本来代替你的思考"

### 从武汉文理模板导入 Layouts

新建 `scripts/LayoutImporter.py`，通过底层XML操作将源PPT的slides转为真正的 `slide_layout`：

1. 解压源和目标PPTX
2. 复制目标模板的空白layout XML
3. 将源slide的非占位符形状复制到新layout
4. 转换为占位符（添加 `p:ph` 标签）
5. 更新 `slideMaster.xml` 的 `sldLayoutIdLst`
6. 更新 `[Content_Types].xml`
7. 重新打包

## 深夜：v5.0 PPT layout 单一化问题 + 图形设计重构

### 问题
用户两次追问：课件_v5.0.pptx 23页全部使用 layout 1（标题和内容），模板16种layouts基本没用上。

### 根本原因
1. **转换脚本设计缺陷**：`convert_v41_to_rich.py` 的 `LAYOUT_MAP` 中 20/23 页映射到 layout 1
2. **内容结构丢失**：`clean_core_content` 把 "左侧/右侧"、时间节点、卡片组等结构信息扁平化为一维列表，编译器无法识别应该用多栏/时间轴/卡片布局
3. **编译器被动执行**：ScriptParser 提取什么 layout 编号，PptxCompiler 就用什么，不会根据内容推断

### 修复方案
**不走转换脚本，手工逐页分析知识点关系，匹配layout。**
