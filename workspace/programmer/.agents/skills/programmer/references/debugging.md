# 调试方法论

> Bug 定位、根因分析、修复验证。

---

## 核心原则

### 先复现，再定位

**无法复现的 Bug 难以修复**。先稳定复现步骤。

### 先定位，再修复

**不要猜测 Bug 位置**。用工具定位，证据驱动。

### 修复后必须验证

修复的 Bug 必须有回归测试。

---

## 判断框架

### Bug 定位优先级

| 优先级 | 类型 | 定位难度 |
|--------|------|----------|
| P0 | 崩溃/数据损坏 | 高 |
| P1 | 核心功能失效 | 高 |
| P2 | 边界条件问题 | 中 |
| P3 | UI/体验问题 | 低 |

### 什么时候扩大搜索范围？

| 现象 | 决策 |
|------|------|
| 单模块定位不到 | 扩大到相关模块 |
| 前端问题但后端日志正常 | 检查网络/协议 |
| 偶发问题 | 检查并发/竞态 |
| 特定环境出现 | 检查环境差异 |

## 定位方法

### 日志分析

| 策略 | 说明 |
|------|------|
| **时间线** | 按时间顺序排列日志 |
| **关键词** | 搜索关键变量/用户ID |
| **traceId** | 串联请求链路 |
| **对比** | 正常 vs 异常的日志差异 |

### 断点调试

| 类型 | 适用场景 |
|------|----------|
| 条件断点 | 特定值触发 |
| 日志断点 | 不中断，只打印 |
| 远程调试 | 生产环境（谨慎） |

### 二分排查

通过排除法快速缩小范围。

```
问题可能在 A/B/C
→ 确认在 A/B
→ 确认在 A
→ 定位到 A 的具体位置
```

---

## 根因分析

### 5 Why 分析法

通过连续追问找到根本原因。

```
Bug: 用户下单失败
1. 为什么？→ 库存服务超时
2. 为什么超时？→ 连接池耗尽
3. 为什么耗尽？→ 连接未释放
4. 为什么未释放？→ 异常分支没有 close
5. 为什么？→ 缺少 try-finally

根因: 异常处理不完整
```

### 修复边界

| 问题 | 修复方式 |
|------|----------|
| 单点问题 | 修复具体位置 |
| 设计缺陷 | 重构设计 |
| 偶发问题 | 增加防御性检查 |

---

## 修复验证

### 必须做的事

| 步骤 | 说明 |
|------|------|
| **复现 Bug** | 确认能复现 |
| **验证修复** | 修复后测试通过 |
| **回归测试** | 确保没破坏其他功能 |
| **补充测试** | 防止再次出现 |
| **记录** | 记录原因和修复方式 |

### 常见错误

| 错误 | 后果 |
|------|------|
| 只测修复的部分 | 新问题没发现 |
| 不复现就修复 | 修复不正确 |
| 猜测修复 | 可能引入新问题 |
| 修复后不验证 | 实际上没修好 |
| 不记录 | 同样的 Bug 再来一次 |
