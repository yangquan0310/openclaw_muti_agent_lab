# OOP 设计

> 封装、继承、多态的适用判断。

---

## 三大概念

| 概念 | 解决的问题 | 滥用后果 |
|------|------------|----------|
| **封装** | 数据被随意访问 | 过度封装，接口繁琐 |
| **继承** | 代码重复 | 继承层次过深，难以理解 |
| **多态** | 替换实现要改代码 | 过度设计，接口复杂 |

---

## 判断框架

### 什么时候用 OOP？

| 场景 | 决策 |
|------|------|
| 有清晰的概念实体 | ✅ 适合 OOP |
| 行为和数据紧密相关 | ✅ 适合 OOP |
| 纯数学计算/数据转换 | ❌ 函数式更合适 |
| 简单脚本 | ❌ 不需要 OOP |

### 什么时候用继承？

表达"是...的一种"时用继承。

**例子**：
```python
class Animal:
    def speak(self): ...

class Dog(Animal):  # Dog 是 Animal 的一种
    def speak(self):
        return "汪"
```

### 什么时候用组合？

表达"有...的关系"时用组合。**优先组合而非继承**。

## 设计模式适用场景

| 类型 | 模式 | 适用场景 |
|------|------|----------|
| 创建型 | Singleton | 全局唯一对象 |
| 创建型 | Factory | 对象创建逻辑复杂 |
| 结构型 | Adapter | 接口不兼容 |
| 行为型 | Strategy | 多种算法可选 |
| 行为型 | Observer | 事件通知 |

**不滥用**：为了用模式而用模式是过度工程。

---

## 常见错误

| 错误 | 问题 |
|------|------|
| 上帝类 | 一个类有 50 个方法 |
| 继承过深 | 超过 3 层 |
| 滥用继承复用代码 | 应该用组合 |
| 过度封装 | 每个小操作都加接口 |
