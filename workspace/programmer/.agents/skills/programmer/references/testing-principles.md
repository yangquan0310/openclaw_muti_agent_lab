# 测试原则

> 为什么要测、测什么。

---

## 为什么要写测试？

| 价值 | 说明 |
|------|------|
| **回归保护** | 修改代码不破坏现有功能 |
| **文档作用** | 测试即文档，说明期望行为 |
| **设计工具** | 写测试迫使思考接口设计 |
| **信心** | 有测试才能敢改代码 |

**没有测试的代码是半成品。**

---

## 判断框架

### 测什么？

| 优先级 | 内容 | 原因 |
|--------|------|------|
| 必须测 | 核心业务逻辑 | 错误代价高 |
| 必须测 | 边界条件 | Bug 高发区 |
| 必须测 | 错误处理 | 系统健壮性 |
| 可不测 | 简单 getter/setter | 价值低 |
| 可不测 | 第三方库 | 他们自己测 |

### 测试金字塔

```
        ┌───────┐
        │  E2E  │  ← 少量，端到端
       ┌┴───────┴┐
       │ 集成测试 │  ← 中量，模块间
      ┌┴─────────┴┐
      │   单元测试  │  ← 大量，核心逻辑
     ┌┴───────────┴┐
```

**单元测试是基础**。没有单元测试的 E2E 测试是脆弱的。

---

## 好测试的特性

| 特性 | 说明 |
|------|------|
| **独立** | 测试间无依赖 |
| **可重复** | 每次运行结果一致 |
| **快速** | 单元测试毫秒级 |
| **自描述** | 从名字知道测什么 |

---

## AAA 模式

| 阶段 | 说明 |
|------|------|
| **Arrange** | 准备测试数据 |
| **Act** | 执行被测操作 |
| **Assert** | 验证结果 |

---

## 不合格模式

| 模式 | 问题 |
|------|------|
| 测试覆盖核心逻辑之外 | 浪费 |
| 测试间相互依赖 | 顺序敏感 |
| 测试太慢 | 没人愿意跑 |
| 断言太宽 | `assertTrue(result)` 这种没意义 |
