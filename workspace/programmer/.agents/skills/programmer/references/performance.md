# 性能优化

> 性能分析、优化策略、缓存策略。

---

## 判断框架

### 什么时候需要性能优化？

| 场景 | 决策 |
|------|------|
| 用户明确投诉慢 | 必须优化 |
| 超过 SLA 要求 | 必须优化 |
| 资源使用率过高 | 必须优化 |
| 功能尚未完成 | 不优化，先完成 |

### 什么时候不要优化？

- 还没测出瓶颈在哪
- 优化代价高于收益
- 代码还没稳定
- 不是性能问题

---

## 性能分析原则

### 先测量，再优化

**不要猜测性能瓶颈**。用工具定位。

| 工具 | 用途 |
|------|------|
| profiling | CPU 热点分析 |
| tracing | 请求链路追踪 |
| monitoring | 运行时指标 |
| logging | 慢查询日志 |

### 优化顺序

1. **算法复杂度**：O(n²) → O(n log n)
2. **数据库**：加索引、减少查询
3. **缓存**：减少重复计算
4. **异步**：非关键路径异步化
5. **代码**：循环优化、内存分配

## 缓存策略

### 缓存层次

| 层次 | 延迟 | 适用场景 |
|------|------|----------|
| 浏览器缓存 | 极低 | 静态资源 |
| CDN | 低 | 公共资源 |
| 内存缓存 | 低 | 热点数据 |
| 数据库缓存 | 中 | 查询结果 |

### 缓存原则

| 原则 | 说明 |
|------|------|
| **命中率高才值得** | 命中率 < 50% 意义不大 |
| **缓存一致性** | 更新时清除缓存 |
| **过期策略** | 平衡新鲜度和性能 |
| **容量控制** | 防止缓存无限膨胀 |

## 并发原则

### 并发风险

| 风险 | 后果 |
|------|------|
| 竞态条件 | 数据不一致 |
| 死锁 | 系统卡死 |
| 资源耗尽 | 服务不可用 |

### 防御原则

| 原则 | 说明 |
|------|------|
| **避免共享状态** | 尽量无状态设计 |
| **原子操作** | 关键操作加锁 |
| **超时机制** | 防止无限等待 |
| **限流熔断** | 防止雪崩 |

---

## 不合格模式

| 模式 | 问题 |
|------|------|
| N+1 查询 | 数据库往返过多 |
| 大表全扫描 | 无索引 |
| 同步等待外部服务 | 拖慢整体 |
| 内存泄漏 | 长时间运行崩溃 |
| 连接池耗尽 | 资源不足 |
