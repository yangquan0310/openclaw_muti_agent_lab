# 全栈开发

> 前端、后端、数据库的协作原则。

---

## 分层原则

```
┌─────────────┐
│   前端      │  ← 不信任，做充分校验
├─────────────┤
│   API 层    │  ← 契约，版本管理
├─────────────┤
│   后端      │  ← 业务逻辑，权限校验
├─────────────┤
│   数据库    │  ← 约束，数据一致性
└─────────────┘
```

---

## API 设计原则

### REST 资源命名

| 原则 | 示例 |
|------|------|
| 用名词不用动词 | `/users` 而非 `/getUsers` |
| 复数资源 | `/users` 而非 `/user` |
| 嵌套资源 | `/users/{id}/orders` |

### HTTP 方法语义

| 方法 | 语义 | 幂等 |
|------|------|------|
| GET | 查询 | ✅ |
| POST | 创建 | ❌ |
| PUT | 全量更新 | ✅ |
| PATCH | 部分更新 | ❌ |
| DELETE | 删除 | ✅ |

### 状态码原则

| 码 | 含义 | 使用场景 |
|------|------|----------|
| 200 | 成功 | 正常返回 |
| 201 | 创建成功 | POST 创建 |
| 400 | 客户端错误 | 参数错误 |
| 401 | 未认证 | 没登录 |
| 403 | 无权限 | 没权限 |
| 404 | 不存在 | 资源不存在 |
| 500 | 服务端错误 | 内部异常 |

## 数据库设计原则

| 原则 | 说明 |
|------|------|
| **范式化** | 减少数据冗余 |
| **外键约束** | 表达表间关系 |
| **索引** | 加速查询，但不是越多越好 |
| **不要 select *** | 明确需要的字段 |

---

## 前后端协作原则

| 原则 | 说明 |
|------|------|
| **接口先行** | 后端 API 文档先于实现 |
| **契约固定** | 接口变更要通知 |
| **充分校验** | 前端和后端都要做校验 |
| **错误友好** | 错误信息要具体 |

---

## 不合格模式

| 模式 | 问题 |
|------|------|
| 接口无文档 | 前后端约定不清 |
| 前后端数据格式不一致 | 返工 |
| 数据库无索引 | 查询慢 |
| select * | 传输冗余数据 |
