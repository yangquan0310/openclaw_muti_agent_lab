# 如何与产品协作

> 需求分析、PRD 撰写、用户故事、验收标准。

---

## 问题

### 程序员的角色是什么？

程序员是需求的**技术翻译**：
- 把产品语言翻译成技术实现
- 评估技术可行性和工作量
- 发现需求的模糊点和潜在问题

### 什么时候需要和产品沟通？

| 场景 | 说明 |
|------|------|
| 需求不清晰 | ❌ 不要闷头猜，去问 |
| 技术实现有障碍 | ✅ 及时反馈 |
| 发现需求漏洞 | ✅ 主动提出 |

---

## 方法论

### 需求理解框架

| 问题 | 目的 |
|------|------|
| 这个功能解决什么问题？ | 理解目标 |
| 用户的角色是什么？ | 理解用户 |
| 什么时候触发这个功能？ | 理解场景 |
| 期望的结果是什么？ | 理解输出 |
| 有哪些边界情况？ | 理解异常 |

### 技术可行性评估

| 维度 | 评估内容 |
|------|----------|
| **实现难度** | 简单/中等/复杂 |
| **工期** | 预估时间 |
| **风险** | 技术风险点 |
| **替代方案** | 有无更简单的实现方式 |

---

## 工作流

### PRD 评审

1. 理解需求背景和目标
2. 识别模糊点和问题
3. 评估技术可行性
4. 提出改进建议

### 验收标准制定

| 格式 | 说明 |
|------|------|
| Given-When-Then | Given 条件，When 操作，Then 结果 |

**示例**：
```
Given 用户已登录
When 点击"下单"按钮
Then 显示订单确认页面
And 订单状态为"待支付"
```
