# 如何进行全栈开发

> 前端、后端、数据库的全栈技术栈与协作方式。

---

## 问题

### 全栈包括哪些层？

```
┌─────────────┐
│   前端      │  ← 用户界面
├─────────────┤
│   API 层    │  ← 接口定义
├─────────────┤
│   后端      │  ← 业务逻辑
├─────────────┤
│   数据库    │  ← 数据存储
└─────────────┘
```

### 每层的技术选型

| 层 | 常见技术 | 选择依据 |
|------|----------|----------|
| 前端 | React/Vue/Angular | 团队熟悉度、项目复杂度 |
| 后端 | Python/Node/Java | 性能要求、团队熟悉度 |
| API | REST/GraphQL | 数据获取模式 |
| 数据库 | PostgreSQL/MySQL/MongoDB | 数据结构、规模 |

---

## 方法论

### REST API 设计原则

| 原则 | 说明 |
|------|------|
| **资源命名** | 用名词：`/users`, `/orders` |
| **HTTP 方法** | GET 查询、POST 创建、PUT 更新、DELETE 删除 |
| **状态码** | 200 成功、400 客户端错误、500 服务端错误 |

### 数据库设计原则

| 原则 | 说明 |
|------|------|
| **范式化** | 减少数据冗余 |
| **外键** | 表达表间关系 |
| **索引** | 加速查询 |

---

## 工作流

### 步骤 1：设计数据模型

1. 识别实体
2. 定义属性
3. 确定关系
4. 设计表结构

### 步骤 2：设计 API

1. 确定 API 端点
2. 定义请求/响应格式
3. 编写 API 文档

### 步骤 3：实现后端

1. 实现数据模型
2. 实现业务逻辑
3. 实现 API 接口

### 步骤 4：实现前端

1. 调用 API
2. 渲染界面
3. 处理用户交互

---

## 执行标准

### 全栈检查清单

- [ ] API 有文档
- [ ] 数据库有索引
- [ ] 前后端数据格式一致
- [ ] 有错误处理
- [ ] 有日志记录
