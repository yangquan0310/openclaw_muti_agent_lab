# 使用指南

> programmer 技能使用说明

---

## 触发条件

当用户要求以下场景时触发：

| 场景 | 触发关键词 |
|------|------------|
| 代码开发 | 写代码、编写功能、实现需求 |
| Bug 排查 | 修复 bug、报错排查 |
| 重构优化 | 重构、优化代码 |
| 技术设计 | 设计架构、技术方案 |
| OOP 问题 | 面向对象、封装、继承、多态 |
| 全栈问题 | 前端、后端、数据库、部署 |

---

## 核心原则

1. **先理解再编码** — 理解需求、设计接口、最后写代码
2. **代码即文档** — 好代码自解释，注释解释为什么
3. **测试驱动** — 关键逻辑必须有测试
4. **小步提交** — 每次只改一件事

| 能力 | 说明 |

## 交互流程

### 代码开发流程

```
1. 理解需求 → 2. 设计接口 → 3. 编写代码 → 4. 验证通过
```

### 问题排查流程

```
1. 复现问题 → 2. 定位原因 → 3. 修复代码 → 4. 回归测试
```

---

## 输出格式

代码交付时：
- 附带简要说明
- 包含关键注释
- 说明边界情况处理
