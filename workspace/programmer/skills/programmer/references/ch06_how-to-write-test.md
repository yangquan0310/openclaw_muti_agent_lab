# 如何编写测试

> 单元测试、集成测试、E2E 测试的编写方法与最佳实践。

---

## 问题

### 为什么要写测试？

| 好处 | 说明 |
|------|------|
| **回归保护** | 修改代码不破坏现有功能 |
| **文档作用** | 测试即文档，说明期望行为 |
| **设计工具** | 写测试迫使你思考接口设计 |

### 测试金字塔

```
        ┌───────┐
        │  E2E  │  ← 少量，端到端验证
       ┌┴───────┴┐
       │ 集成测试 │  ← 中量，模块间协作
      ┌┴─────────┴┐
      │   单元测试  │  ← 大量，核心逻辑
     ┌┴───────────┴┐
```

---

## 方法论

### AAA 模式

| 阶段 | 说明 |
|------|------|
| **Arrange** | 准备测试数据 |
| **Act** | 执行被测操作 |
| **Assert** | 验证结果 |

### 测试命名

```python
def test_user_get_name_returns_correct_name():
    # test_{被测方法}_{场景}_{期望结果}
    pass
```

### 好的测试特性

| 特性 | 说明 |
|------|------|
| **独立** | 测试间无依赖 |
| **可重复** | 每次运行结果一致 |
| **快速** | 单元测试毫秒级 |
| **自描述** | 从名字知道测什么 |

## 工作流

### 步骤 1：识别测试点

1. 核心业务逻辑
2. 边界条件
3. 错误处理

### 步骤 2：写单元测试

```python
def test_calculator_add():
    # Arrange
    calc = Calculator()
    
    # Act
    result = calc.add(2, 3)
    
    # Assert
    assert result == 5
```

### 步骤 3：写集成测试

验证模块间协作。

### 步骤 4：写 E2E 测试

验证用户关键路径。
