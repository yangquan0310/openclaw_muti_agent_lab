# 如何进行开发

> 从需求到交付的开发全流程，包括需求理解、技术设计、编码、测试、部署。

---

## 问题

### 开发的核心流程是什么？

```
需求理解 → 技术设计 → 编码实现 → 测试验证 → 代码审查 → 部署交付
```

### 每个阶段的核心产出是什么？

| 阶段 | 核心产出 | 负责角色 |
|------|----------|----------|
| 需求理解 | 明确的问题定义 | 程序员 + 产品 |
| 技术设计 | 架构图 + 接口定义 | 程序员 |
| 编码实现 | 可运行的代码 | 程序员 |
| 测试验证 | 通过的测试用例 | 程序员 |
| 代码审查 | 审查意见 | 同伴 |
| 部署交付 | 上线的功能 | DevOps/程序员 |

---

## 方法论

### 四步法则

| 法则 | 说明 |
|------|------|
| **理解全貌再动手** | 改代码前先理解上下文和影响范围 |
| **蓝图先于实现** | 架构设计完成、接口明确后再编码 |
| **接口即契约** | 模块间通过清晰接口协作，降低耦合 |
| **小步提交** | 每次只改一件事，频繁验证 |

### 判断：什么时候需要技术设计？

| 场景 | 是否需要设计 |
|------|--------------|
| 新项目/新模块 | ✅ 必须 |
| 修改核心逻辑 | ✅ 必须 |
| 多人协作 | ✅ 必须 |
| Bug 修复 | ❌ 可跳过 |
| 小改动 | ❌ 可跳过 |

## 工作流

### 步骤 1：理解需求

1. 明确要解决什么问题
2. 确定输入和输出
3. 识别边界情况和异常
4. 识别依赖（外部服务、库）

### 步骤 2：技术设计

1. 划分模块/类
2. 定义接口
3. 画架构图（如果是新项目）
4. 评估技术选型

### 步骤 3：编码实现

1. 创建测试用例（TDD 可选）
2. 实现核心逻辑
3. 实现边界处理
4. 添加必要注释

### 步骤 4：测试验证

1. 运行单元测试
2. 手动验证核心功能
3. 检查边界情况

### 步骤 5：代码审查

1. 发起 PR/MR
2. 响应审查意见
3. 合并代码

### 步骤 6：部署交付

1. 更新版本号
2. 部署到测试环境
3. 验证功能
4. 部署到生产环境

## 执行标准

### 各阶段检查

| 阶段 | 检查项 | 通过标准 |
|------|--------|----------|
| 需求理解 | 问题清晰 | 能用自己的话复述 |
| 技术设计 | 接口明确 | 其他模块可以基于接口开发 |
| 编码 | 功能正确 | 所有测试通过 |
| 测试 | 覆盖充分 | 关键路径有测试 |
| 审查 | 无重大问题 | 无 blocker |
| 部署 | 回滚预案 | 知道如何回滚 |

### Git 提交规范

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| refactor | 重构 |
| docs | 文档更新 |
| test | 测试更新 |
| chore | 杂项 |
