# 如何进行 OOP 设计

> 面向对象核心概念：封装、继承、多态，以及设计模式。

---

## 问题

### OOP 的三大支柱

| 概念 | 说明 | 解决的问题 |
|------|------|------------|
| **封装** | 数据和对数据的操作放在一起 | 数据被随意访问 |
| **继承** | 子类复用父类的属性和行为 | 代码重复 |
| **多态** | 同一接口，不同实现 | 替换实现需要改代码 |

### 什么时候用 OOP？

| 场景 | 判断 |
|------|------|
| 有清晰的概念实体 | ✅ 适合 OOP |
| 行为和数据紧密相关 | ✅ 适合 OOP |
| 纯数学计算/数据转换 | ❌ 函数式更合适 |
| 简单脚本 | ❌ 不需要 OOP |

## 方法论

### 封装

**原则**：对外提供接口，隐藏内部实现

```python
class User:
    def __init__(self, name: str):
        self._name = name  # 私有属性
    
    def get_name(self) -> str:  # 公开接口
        return self._name
```

### 继承

**原则**：用继承表达"是...的一种"

```python
class Animal:
    def speak(self): ...

class Dog(Animal):  # Dog 是 Animal 的一种
    def speak(self):
        return "汪"
```

### 多态

**原则**：同一消息，不同响应

```python
def make_speak(animal: Animal):
    return animal.speak()  # 同一调用，不同结果
```

### 设计模式

| 类型 | 模式 | 适用场景 |
|------|------|----------|
| **创建型** | Singleton | 全局唯一对象 |
| **创建型** | Factory | 对象创建逻辑复杂 |
| **结构型** | Adapter | 接口不兼容 |
| **行为型** | Strategy | 多种算法可选 |
| **行为型** | Observer | 事件通知 |

## 工作流

### 步骤 1：识别概念

从需求中提取关键实体/概念。

### 步骤 2：定义职责

每个类的职责是什么？它应该做什么？

### 步骤 3：设计关系

- "是...的一种" → 继承
- "有...的关系" → 组合
- "使用...完成工作" → 依赖

### 步骤 4：应用模式

根据场景选择合适的设计模式。

## 执行标准

### OOP 检查清单

- [ ] 类名是名词
- [ ] 方法名是动词
- [ ] 每个类只有一个职责
- [ ] 继承层次不过深（< 3 层）
- [ ] 优先组合而非继承
- [ ] 封装保护内部状态
