# 论文阅读 SOP（数学家版）

> 数学家阅读论文的标准作业流程。  
> **核心原则**：读完一篇论文，必须能在 wiki 里反查到证据链（`raw/ → sources/ → syntheses/`），并向老板交付可验证的"待确认项"。

---

## 一、阅读前清单（必做，不打勾不开始）

> **为什么需要清单**：数学家常被论文的复杂结构带偏方向。先定边界，再读细节。

| # | 决策项 | 自问 | 输出 |
|---|--------|------|------|
| 1 | **读这篇论文的目的是什么？** | 是补充知识背景 / 找方法借鉴 / 复现实验 / 找新方向？ | 一句话（写进笔记"动机"段） |
| 2 | **预期产出是什么？** | 一句话总结 + 关键内容 + 待确认 / 完整复现报告 / 概念页 / 综述？ | 明确交付物 |
| 3 | **本论文在证据链中的位置？** | 是 raw 原始资料 / 已有 source summary / 已有 synthesis？ | 决定落位到 `raw/`、`sources/` 还是 `syntheses/` |
| 4 | **与哪些已有 wiki 页面相关？** | 查 wiki（`wiki_search`）找同主题、同方法、同作者的页面 | 反查链接候选清单 |
| 5 | **阅读优先级** | 三遍阅读法的第几遍？时间预算？ | 计划 |

**模板**（笔记开头直接复制粘贴）：

```markdown
## 阅读前清单
- 目的：[补充背景 / 方法借鉴 / 复现 / 新方向]
- 预期产出：[一句话总结 + 待确认 / 完整复现 / 概念页 / 综述]
- 落位：[raw/ sources/ syntheses/]
- 相关 wiki 页：[链接 1]、[链接 2]
- 优先级：[第 X 遍 / 时间预算 X 小时]
```

## 二、raw / sources / syntheses 证据链（核心规范）

> **绝对不能跳过**——这是 wiki 的"证据层"。每个 raw 资料必须有对应的 source summary，syntheses 笔记必须可回溯到 raw。

### 2.1 三层目录的角色

| 目录 | 角色 | 处理深度 | 写入规则 |
|------|------|----------|----------|
| `raw/` | **证据层**，存放原始文件 | 零处理——只归档 | 文件原样存放 |
| `sources/` | **来源摘要**，每个 raw 一个 | 轻提炼——一句话 + 关键 + 影响 + 待确认 | 按 `_template_source_summary.md` 模板 |
| `syntheses/` | **综述**，综合多 source | 重提炼——多源 + 论证 + 结论 | 必须 source-backed |
| `concepts/` `entities/` | 抽象层 | 概念 / 实体的归纳 | 跨多 source 抽象 |
| `reports/` | 客观报告 | 可重复生成 | 仅可验证事实 |

### 2.2 命名约定（与 `wiki/raw/README.md` 一致）

| 类型 | 格式 | 示例 |
|------|------|------|
| 论文 PDF | `YYYY-MM-DD_<作者>_关键词_期刊.pdf` | `2026-05-31_Al-Kari_Cognitive-Categorical-Transformer_arXiv.pdf` |
| 论文笔记（source summary） | 与 PDF 同名，扩展名 `.md` | `2026-05-31_Al-Kari_Cognitive-Categorical-Transformer_arXiv.md` |
| 综述笔记 | `YYYY-MM-DD-HH-MM-SS-<标题>.md`（17 字符紧凑时间戳） | `2026-05-31-11-00-00-CCT-论文笔记.md` |

> ⚠️ **`YYYY-MM-DD` 是归档日期，不是论文发表日期**。发表日期写进 source summary 的 frontmatter。

### 2.3 落位决策树

```
拿到一篇论文
    │
    ▼
是 raw 原始资料（PDF/HTML/Markdown 原文）？
    │
    ├── 是 → 移动到 wiki/raw/<category>/，按命名约定重命名
    │         │
    │         ▼
    │      在 wiki/sources/ 创建 source summary（轻提炼）
    │
    └── 否（已是 source summary 或 notes）
              │
              ▼
          引用到 syntheses/（重提炼）或概念/实体页
```

### 2.4 反向链接（wikilink）规范

| 规则 | 说明 |
|------|------|
| **每个 raw 文件必有一个 source summary 反向引用** | 形式：`[[raw/papers/<file>.pdf]]` |
| **每个 synthesis 笔记必指向至少一个 sources/ 笔记** | 形式：`[[sources/<file>.md]]` |
| **frontmatter `sourceIds` 必须是 raw 文件路径** | 形式：`raw/papers/<file>.pdf`，**不是** arXiv ID |
| **正文使用 `[[wikilink]]` 而非 markdown 链接** | 模板要求，wiki 双向链接系统依赖此格式 |

> ⚠️ **lint 已知限制**：`[[raw/...pdf]]` 形式的 wikilink 会被 lint 工具报"Broken wikilink target"，但实际 PDF 存在。这是文本 lint 工具不能解析二进制目标的局限，**不是真断链**。按模板使用 wikilink 即可。

## 三、三遍阅读法

### 第一遍：鸟瞰（30-60 分钟）

**目标**：判断**值不值得深入**。

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | 读标题、摘要、引言前两段、结论 | 一句话总结能否写在卡片上？ |
| 2 | 浏览所有图表与表头（不细看） | 论文的"骨架图"是什么？ |
| 3 | 读相关工作（Related Work） | 这篇和已有 X 篇是什么关系？ |
| 4 | 看参考文献 | 有没有我已知的奠基性工作？ |

**决策点**：
- ✅ 值得深入 → 进入第二遍
- ❌ 不值得 → 写一句 source summary（一句话总结 + 落位到 `sources/`），关闭

### 第二遍：理解（2-4 小时）

**目标**：理解**方法核心 + 实验设计**。

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | 通读全文，不查细节 | 写出一句话总结（"这篇最重要的 takeaway"） |
| 2 | 重读方法部分，逐公式过 | 把核心数学公式抄到笔记（**手抄，不要复制 PDF**） |
| 3 | 重读实验部分，看表格 | 列出主要消融与对应数字 |
| 4 | 找负面结果（见第四节） | 哪些实验**失败**了？作者怎么解释？ |
| 5 | 检查复现性（见第五节） | 论文给了什么可复现资产？ |

**产出**：
- 笔记草稿（结构：动机 / 方法 / 实验 / 负面结果 / 待确认）
- source summary 草稿（按模板）

### 第三遍：批判（1-2 小时）

**目标**：**质疑**——找论文没说、没说清、说不通的地方。

| 质疑维度 | 检查点 |
|----------|--------|
| **方法论** | 实验是否 matched？对照是否公平？基线是否最新？ |
| **统计** | 多种子？置信区间？显著性检验？ |
| **可推广性** | 单数据集？单尺度？单语言？ |
| **数学严密性** | 关键步骤是否跳步？定理是否给完整证明？ |
| **代码** | 是否公开？可独立运行？ |
| **引用** | 关键引文是否断章取义？ |

**产出**：
- "待确认项"清单（**见第七节**）
- 反查相关工作（**见第六节**）

## 四、负面结果记录（必须有专门一节）

> **为什么单独强调**：负面结果往往比正面结果更接近真相。论文里写"我们试了 X，效果不好"——这是**高价值信息**，必须显式记录。

### 4.1 必记录的内容

```markdown
## 负面结果

| 实验 | 预期 | 实际 | 作者解释 | 我的解读 |
|------|------|------|----------|----------|
| 实验名 | 假设效果 | 数字 / 方向 | 论文原话或转述 | 是否合理？有没有更合理解释？ |
```

### 4.2 必问的负面问题

- [ ] 哪些**理论应该work**但实际 fail？
- [ ] 哪些**先验假设**被证伪？
- [ ] 哪些**消融**显示某组件**负贡献**？
- [ ] 哪些**超参搜索**搜不到任何改善？

### 4.3 真实案例（CCT 论文的负面结果）

| 类型 | 内容 | 教训 |
|------|------|------|
| 失败组件 | Sheaf 一致性损失、曲率正则化、伴随往返损失 | "添加一致性约束"无效 → **结构先验 vs 一致性先验** 区分 |
| 条件依赖 | PrecisionWeightedPP 在 RC2 贡献 1.40 PPL，在 E2 仅 0.07 PPL | 组件贡献**条件依赖**于其他组件 |
| 方法论警示 | eval-only 消融高估 GT-Full 贡献 91.6%，retrain-from-scratch 才给出真实 84% | 消融方式决定结论可信度 |

## 五、代码与复现性检查

> **为什么必做**：数学家常需要复现论文实验以验证方法。

### 5.1 检查清单

| # | 检查项 | 关键问题 | 缺失的影响 |
|---|--------|----------|------------|
| 1 | **代码** | GitHub 链接？版本号？可独立运行？ | 无法验证实现细节 |
| 2 | **数据** | 公开？许可证？预处理脚本？ | 无法对齐数据 |
| 3 | **模型权重** | 检查点？预训练来源？ | 无法从同起点复现 |
| 4 | **超参** | 学习率、批大小、优化器、调度器、步数 | 消融结论不可信 |
| 5 | **随机种子** | 单种子？多种子？方差？ | 数字可能不显著 |
| 6 | **计算资源** | GPU 型号、显存、训练时长 | 不可比性 |
| 7 | **评估协议** | 指标定义、数据切分、prompt 模板 | 数字不可比 |
| 8 | **许可证** | 代码 / 数据的 license | 商业可用性 |

### 5.2 matched-step 协议（消融的"金标准"）

> **核心思想**：被测架构与基线**共享**所有可共享的变量，唯一差异是**架构增强**。

| 必须 matched 的变量 | 原因 |
|---------------------|------|
| backbone 初始化 | 起点相同 |
| 训练语料 | 数据差异不混入 |
| 优化器 | 优化动力学相同 |
| 步数预算 | 训练量相同 |
| 学习率调度 | 收敛轨迹相同 |
| 数据切分 | 评估起点相同 |

**如果论文没 matched**，记录到"待确认"，并在 source summary 标注"方法论可信度：低/中/高"。

### 5.3 消融的两类方式

| 方式 | 做法 | 优点 | 缺点 | 何时用 |
|------|------|------|------|--------|
| **eval-only** | 训练后移除组件 | 省算力 | 高估组件贡献（模型已适应组件输出） | 仅做"依赖性"诊断 |
| **retrain-from-scratch** | 从初始化起禁用组件 | 真实架构贡献 | 算力昂贵 | **唯一可信的"贡献分解"** |

## 六、与同领域论文对比

> **为什么必做**：单论文永远是局部视角。要形成"领域地图"。

### 6.1 对比维度

| 维度 | 问题 |
|------|------|
| **任务** | 同任务？相近任务？ |
| **方法** | 同范式（如同样基于图、同样基于 transformer）？ |
| **数据** | 同数据集？同规模？ |
| **指标** | 同指标？可换算？ |
| **规模** | 参数 / 数据 / 算力是否可比？ |
| **创新点** | 是同方向的延续？平行替代？还是突破？ |

### 6.2 对比模板

```markdown
## 与同领域论文对比

| 论文 | 任务 | 方法 | 规模 | 主要数字 | 与本论文关系 |
|------|------|------|------|----------|--------------|
| 论文A | ... | ... | ... | ... | 同方向/基线/平行 |
| 论文B | ... | ... | ... | ... | ... |
```

### 6.3 关键问题

- [ ] 这篇论文 vs 它的"前一篇"——进步在哪？退步在哪？
- [ ] 这篇论文的"基线"——是不是**最新最强**的基线？还是用过时的？
- [ ] 这篇论文的"sota"声明——sota 是在哪个维度？是真 sota 还是 cherry-pick？
- [ ] 同一作者的其他工作——这是系列中的第几篇？积累的"叙事弧"是什么？

## 七、"待确认项"规范（必须暴露脆弱性）

> **核心原则**：source summary 里的"待确认"不是失败列表，是**有意暴露的脆弱性**——任何不确定的事实、解读分歧、引用位置犹豫，都要写出来。

### 7.1 必记录的 5 类待确认

| 类别 | 示例 |
|------|------|
| **事实疑点** | "论文称 X 在 Y 上达到 90%，但我无法在 Table Z 复现这个数字" |
| **解读分歧** | "论文把负面结果归因于 A，但我认为更可能是 B（理由：...）" |
| **引用位置** | "数学家 A 的证明在原论文第 4 节还是附录？我手头没有原文" |
| **复现性** | "代码未公开，架构细节无法独立验证" |
| **方法论可信度** | "matched-step 协议不严格，参数预算不固定" |

### 7.2 待确认项的格式

```markdown
## 待确认

- [ ] **单种子问题**：实验仅 seed=42，84%/2.45 PPL 这个核心数字需多种子复现
- [ ] **代码未公开**：架构细节（k=6、三角形稀疏加速 2500×、DNC 三层容量）无法独立验证
- [ ] **PP 条件依赖的因果性**：观察是相关性，PP 是否需要 GT-Full 的特定输出分布还是任何结构化输入均可，尚无消融
```

### 7.3 何时升级"待确认"为"行动项"

| 信号 | 行动 |
|------|------|
| 多个 wiki 页面都标记了同一待确认 | 升级为综述笔记的"开放问题" |
| 老板的某个研究方向依赖该待确认 | 安排复现或调研 |
| 待确认是**事实疑点**（不是解读分歧） | 安排代码复现或读相关论文 |

## 九、常见错误（反面教材）

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| ❌ PDF 放在 `temp/papers/` 不归档 | 半年后找不到，且不参与 wiki 索引 | **第一步就归档**到 `raw/` |
| ❌ 只写 synthesis，不建 source summary | 反查链断，老板无法核证 | **每个 raw 必配一个 source summary** |
| ❌ frontmatter `sourceIds` 写 `arxiv:xxx` | wiki 无法反查 | 写 `raw/papers/<file>.pdf` |
| ❌ 笔记里"待确认"栏写成空 | 老板不知道哪里脆弱 | **每篇笔记必有 3+ 条**待确认 |
| ❌ 把负面结果混在正面里 | 真相被淹没 | **单独一节**，表格化 |
| ❌ 复现性检查跳过 | 高估论文可信度 | **必做**，缺失要标注 |
| ❌ 名字命名为作者首字母缩写 | 不知道是谁 | **全名或机构+et al.** |
| ❌ 把"我"的解读写成"论文说的" | 失实 | 区分"作者说"和"我说" |
