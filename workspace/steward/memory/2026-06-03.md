**5+1 步流程**：
```
[1] 大管家 create card（--session, 默认 backlog）
[2] 大管家 IM 群艾特代理（IM 模板，task_desc 抬头）
[3] 代理 claim（workboard_claim 插件工具 + 群里回"已认领"）

[5] 代理执行（chat.send 触发 run）
[6] 代理执行完 → 群里发完成消息 + workboard_proof
[7] 大管家核验 → workboard.move → done / blocked
```

## 三、新发现

### 1. Dashboard 限制（v1.4.0 重要踩坑）

**不能点 Dashboard 的"开始"按钮**：
- Dashboard 控制台 `Ix()` 硬编码 `sessions.create`，无视卡上 sessionKey
- 点"开始"会强制建新 session，覆盖卡上 `oc_983c895...` → 变成 `agent:writer:dashboard:...`
- **必须**用 CLI `manager workboard start --id <card>`（v1.4.0+ 修复后真复用）

### 2. Dx 自动同步行为（v1.4.0 发现）

Dashboard Dx 函数在控制台打开时会**自动**把卡状态同步到 session 状态：
- session 是 `done` → 卡 → `review`
- session 是 `running` → 卡 → `running`
- session 是 `failed` → 卡 → `blocked`
- session 是 `idle` / `missing` → 卡不动

**为什么 `--session` 配默认 backlog**：
- Dx **不会**从 `backlog` 同步出去（backlog 是稳态）
- 防止"配齐但被 Dx 乱动"

### 3. start 内部真触发 run（v1.4.0 关键修复）

旧版：start 只改卡元数据，不触发 run（卡 = running 但 agent 不在群里）
新版：start 调 `chat.send` 触发新 run（带 `idempotencyKey` 防重复）

**复用 vs 新建**：
- `--session X`：强制用 X
- 不传 `--session`：复用卡上 sessionKey（如果有消息历史）
- `--no-reuse`：永远 sessions.create 新建

### 5. 模板分离的隐含价值

把 IM 模板和 notes 模板分开后：
- IM 群消息变短（不包目标/约束/输入/产出）
- 群里只看"认领"信息，技术细节在卡上
- 避免群里和卡上数据不一致（群里改了，卡上还是旧的）
- 子代理在卡上 notes 看到的永远是权威信息
