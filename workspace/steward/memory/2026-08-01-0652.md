## 根因诊断 —— session 被你我的对话占用了

cron 配置里：
```
"sessionTarget": "session:agent:steward:corn:steward的定时任务"
```

这是个**持久会话**。但**现在这个 cron 会话就是我和你聊天的 webchat 会话**（runtime 信息显示 sessionKey 一模一样）。cron 想开新 isolated agent，但持久会话被当前的 webchat 占着 → 抢会话失败 → `CronSessionLifecycleClaimError`。

## 对比 —— 别的 cron 为什么没事

`dde9b3aa`（招聘信息）和 `7a700f52`（版本检查）也是同一个 `sessionTarget`，但它们**在没会话占着的时候**自然运行（06:00 / 08:20 你不在聊天），所以不冲突。

## 解决方案 —— 把 sessionTarget 改成 `isolated`

每个 cron run 用**全新 ephemeral session**，不与任何持久会话冲突。这是 cron job 的标准做法。

```diff
- "sessionTarget": "session:agent:steward:corn:steward的定时任务"
+ "sessionTarget": "isolated"
```
