# 任务约束目标指南

> 领取任务时，必须明确约束目标。约束目标不清晰，任务无法推进。

---

## 一、约束目标的本质

约束目标 = **验收标准** + **边界条件**

| 要素 | 说明 | 示例 |
|------|------|------|
| **验收标准** | 任务完成的条件是什么 | "生成一份PDF文件" |
| **边界条件** | 什么不能做、什么范围外 | "不修改其他文件" |

拿到任务后，第一件事不是开始执行，而是先问清楚：完成的标准是什么？哪些事情不在范围内？没有约束目标的任务，不应该推进。

---

## 二、约束目标清单（领取任务时必查）

### 产出约束

- **产出形式**：文件？消息？代码？文档？
- **产出路径**：保存到哪个目录？文件名是什么？
- **产出格式**：Markdown？PDF？DOCX？PPTX？

### 质量约束

- **完成标志**：什么状态算"完成"？
- **验收方式**：谁来验收？通过文件状态判断？

### 边界约束

- **范围限定**：只做 XX，不做 YY
- **权限边界**：可以读什么？不可以写什么？
- **协作边界**：谁来主导？谁来配合？

---

## 三、约束目标确认流程

```
领取任务
    ↓
【必做】询问约束目标（如果用户未主动给出）
    ↓
记录到 TODO.md 的任务描述中
    ↓
按约束目标执行
    ↓
以约束目标为标准验收
```

### 约束目标不明确时的提问模板

```
❓ 约束目标确认：

1. 产出形式是？（文件/消息/代码）
2. 保存路径是？（全路径）
3. 完成标志是？（文件存在/TODO更新/用户确认）
4. 范围边界是？（只做 XX，不做 YY）
5. 验收方式是？（自动验收/手动确认）
```

---

## 四、常见约束目标模式

| 场景 | 约束目标模式 |
|------|--------------|
| 整理项目 | "创建标准目录结构，不移动保护文件，更新 metadata.json" |
| 写作任务 | "输出 Markdown 文件到 manuscripts/，不超过 5000 字，不添加新引用" |
| 审核任务 | "输出审稿意见到 manuscripts/审稿意见.md，列出 P0/P1/P2 问题" |
| 编译任务 | "生成 PDF 到 outputs/，0 警告，文件大小 < 5MB" |

## 五、约束目标与 TODO.md

约束目标是 TODO 任务描述的核心组成部分。领取任务后立即写入 TODO.md，与任务本身绑定。

### TODO 任务格式

```markdown
- [ ] T{序号} {任务名称}
  - **约束目标**：
    - 产出：{文件路径 + 格式}
    - 完成标志：{什么状态算"完成"}
    - 边界：{不做的事}
    - 验收：{谁来验收、如何验收}
```

### 示例

```markdown
- [ ] T003 整理「数字化存储与自传体记忆」项目
  - **约束目标**：
    - 产出：标准目录结构（uploads/manuscripts/knowledge/）
    - 完成标志：README.md 在根目录、metadata.json 已更新
    - 边界：不移动 README.md、HANDBOOK.md、TODO.md
    - 验收：大管家自验后汇报
```

### 约束目标变更

任务推进中发现约束目标需要调整，必须先更新 TODO.md，再通知相关代理。禁止在 TODO 之外单方面修改任务范围。
