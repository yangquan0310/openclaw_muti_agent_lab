# 课程管理指南

> 当用户提到"课程"、"备课"、"课件"、"教学"、"章节"、"教案"、"ppt"或要求整理/管理课程备课项目时，使用本指南。

---

## 一、课程项目的本质

课程项目是以**教案为核心**的教学材料生产工作流。大管家的职责是维护课程框架、管理备课阶段、把控产出质量。

课程项目不负责教学内容本身，由专业的教员、心理学家、呈现师等角色协作完成。

---

## 二、适用项目类型

| 项目类型 | 示例 |
|----------|------|
| 新开课程 | 认知心理学（32学时） |
| 课程迭代 | 实验心理学（2025春 → 2025秋） |
| 章节修订 | 第3章实验设计内容更新 |
| 多人协作备课 | 五人组同时备多章 |

---

## 三、标准目录结构

```
课程项目/
├── README.md              # 项目总览（必须根目录）
├── AGENTS.md            # 项目操作手册（必须根目录）
├── TODO.md                # 任务看板（必须根目录）
├── metadata.json          # 机器可读配置（必须根目录）
│
├── syllabus/             # 教学大纲
├── chapters/             # 章节内容
│   └── ch*_*/
├── shared/              # 共享资源
│   ├── templates/       # 课件模板
│   └── materials/       # 教学材料
├── uploads/             # 上传的原始文档
├── archive/             # 历史版本归档
├── temp/                # 临时文件
│
└── .agents/
    └── agents/          # 代理角色规范
```

**四个契约文件**必须在根目录，缺一不可。

---

## 四、角色分工

| 角色 | 职责 | 边界 |
|------|------|------|
| **instructor** | 课程框架、内容设计 | 不负责学术深度 |
| **psychologist** | 学术内容审核、理论补充 | 不修改课件结构 |
| **presenter** | PPT制作、视觉呈现 | 不提供学术观点 |
| **auditor** | 质量监督、进度把控 | 不直接参与备课 |

---

## 五、备课流水线

```
v1(需求分析)
   ↓
v2(内容框架)
   ↓
v3(内容补充) ←── psychologist 的修改意见
   ↓
v4(终稿教案)
   ↓
v5(审校意见) ←── auditor 的修改意见
   ↓
v6(课件pptx) ←── presenter 制作
   ↓
v7(Git提交+收工)
```

| 轮次 | 产出 | 负责人 |
|------|------|--------|
| v1 | 需求分析 | instructor |
| v2 | 内容框架 | instructor |
| v3 | 内容补充（学术前沿+教学案例） | psychologist |
| v4 | 终稿教案 | instructor |
| v5 | 审校意见 | auditor |
| v6 | 课件pptx | presenter |
| v7 | Git提交+收工 | 大管家 |

## 六、整理流程

当用户要求整理课程项目时，按以下步骤执行：

**第一步：检查现状**。查看当前目录结构、文件分布，判断是否需要保护特殊文件。

**第二步：识别类型**。判断属于新课程/迭代/修订中的哪一种。

**第三步：确认需求**。拿捏不准时，向用户确认："这个项目有特殊文件需要保护吗？"

**第四步：执行整理**。创建标准目录、按规则移动文件、更新 metadata.json。

**第五步：验证结果**。检查四个契约文件是否在根目录，TODO.md 是否需要更新。

**第六步：汇报用户**。输出整理摘要。
