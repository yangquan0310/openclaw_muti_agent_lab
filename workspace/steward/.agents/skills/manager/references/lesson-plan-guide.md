> **修正前版本严重落后**：v4 课件脚本 / v6 终稿教案 顺序错，v7 收工完全缺失——已作废。

## 一、备课角色

| 角色 | Agent ID | 职责 |
|------|----------|------|
| 大管家 | steward | 协调进度、文档管理、版本控制、收工整合 |
| 教员 | instructor | 教学目标、内容架构、知识框架、终稿教案 |
| 心理专家 | psychologist | 前沿学术内容、研究进展、内容补充 |
| 呈现师 | presenter | 课件制作、可视化、pptx 编译 |
| 督导 | auditor | 质量审核、标准检查、审校意见 |

---

## 二、备课流水线（v1-v7，严格串行）

```
v1(需求分析)
   ↓
v2(内容框架) ←── v3(内容补充) 的修改意见
   ↓
v4(终稿教案) ←── v5(审校意见) 的修改意见
   ↓
v6(课件pptx)
   ↓
v7(Git提交+收工)
```

| 轮次 | 文件名 | 主导角色 | 产出内容 | 反馈方向 |
|------|--------|----------|----------|----------|
| v1 | `v1_需求分析.md` | instructor | 教学目标、重难点、课时分配、案例需求 | — |
| v2 | `v2_内容框架.md` | instructor | 三层知识结构、知识点清单、课时分配 | ← 接收v3反馈 → v2.1 |
| v3 | `v3_内容补充.md` | psychologist | 学术前沿、教学案例（**v2 完成后串行启动**） | → 向v2提意见 |
| v4 | `v4_终稿教案.md` | instructor | 整合v1-v3，融合案例内容，输出终稿 | ← 接收v5反馈 → v4.1 |
| v5 | `v5_审校意见.md` | auditor | 审核v4教案内容 | → 向v4提意见 |
| v6 | `v6_课件pptx` | presenter | 基于v4终稿教案编译pptx | — |
| v7 | （Git commit + 飞书传递） | steward | Git提交、收工 | — |

> **关键约束**（**硬规范，违反即不合规**）：
> - **严格串行**：v3 等 v2 完成后启动；v4 等 v3 + v2.1 完成后启动；v5 等 v4 完成后启动；v6 等 v5 + v4.1 完成后启动；v7 等 v6 完成后启动
> - **反馈循环**：v3→v2 形成 v2.1（在 v2 文件上直接修改，不创建分支）；v5→v4 形成 v4.1
> - **每个轮次只生成一份文件**，直接在文件上修改，不创建分支版本
> - **命名严格**：v1/v2/v3/v4/v5/v6（**禁止 v2b 等变体命名**）
> - **每个阶段不可越级**：v4 是终稿教案不是课件脚本，v6 是课件 pptx 不是终稿教案

## 三、v1 需求分析规范

- 产出：`v1_需求分析.md`
- 主导：instructor
- 内容：
  - 目标学生画像（专业/年级/人数/学习形式）
  - 学情分析（前置章节支撑 + 学习特点优劣势）
  - 教学目标（知识/能力/素养三维）
  - 重难点分析
  - 90 分钟课时分配方案（导入 5 + 第一节 25 + 第二节 45 + 第三节 8 + 总结 5 + 过渡 2 = 90 min）
  - 案例需求说明
- 严格基于教材原始内容，不引入教材外新概念

---

## 四、v2 内容框架规范

- 产出：`v2_内容框架.md`
- 主导：instructor
- 输入：v1 需求分析 + 教材
- 内容：
  - 三层知识结构（教材章节的逻辑层次）
  - 知识点清单（13-15 个 + 难度标记 + 课时归属）
  - 概念关系图（3-5 个）
  - 案例选取建议
  - 90 min 课时分配细化
- 接收 v3 反馈后修订为 v2.1（**不创建分支文件**，直接在 v2 文件上修改）

---

## 五、v3 内容补充规范

- 产出：`v3_内容补充.md`
- 主导：psychologist
- 输入：v1 + v2 + 教材
- 内容：
  - 基于教材的前沿学术补充（**不引入教材外新概念**，核心约束）
  - 教材案例的理论谱系（用教材已有术语解读）
  - 国际前沿议题（用教材视角引用）
  - 检索报告归入 `knowledge/检索报告_v3.md`
- 完成后向 v2 提修改建议清单（建议数量不限，质量为先；参考 ch10 v3 范式 6 条）

---

## 六、v4 终稿教案规范

- 产出：`v4_终稿教案.md`
- 主导：instructor
- 输入：v1 + v2.1 + v3
- 内容：
  - 融合 v1（目标/重难点/分配）+ v2.1（内容框架）+ v3（学术补充）全部产出
  - 完整 90 min 教案（教师活动 + 学生活动 + 板书 + 案例引用）
  - 思考题答案
- 接收 v5 审校反馈后修订为 v4.1（**不创建分支文件**，直接在 v4 文件上修改）

---

## 七、v5 审校意见规范

- 产出：`v5_审校意见.md`
- 主导：auditor
- 输入：v4 终稿教案
- 内容：
  - 教材知识点覆盖核查（100% 覆盖）
  - 内容准确性核查
  - 逻辑结构核查
  - 案例与教材匹配度
  - 引用规范核查
  - P0/P1/P2 问题清单
- 完成后向 v4 提修改建议清单
- **P0 必改**（教员必须修订）；P1 建议改；P2 可选

---

## 八、v6 课件 pptx 规范

- 产出：`slides/教育科学研究方法_第N章.pptx`
- 主导：presenter
- 输入：v4 终稿教案（融合 v1-v3 + v5 反馈）
- 内容：
  - 基于 v4 编译 pptx
  - 页数根据内容需要灵活确定（参考 ch10 范式 20 页）
  - 视觉设计与品牌一致
- 命名规范：`教育科学研究方法_第N章.pptx`（如 ch14 → `教育科学研究方法_第十四章.pptx`）

---

## 九、v7 收工规范

- 主导：steward
- 输入：v1-v6 全部产出
- 内容（**大管家专属**，其他代理不参与）：
  1. Git commit（main + development 分支，章节备课完成 → 双分支推送）
  2. v4 终稿教案编译 docx → `docs/教育科学研究方法_第N章.docx`
  3. 飞书群传递 pptx + docx（用 `message` 工具发到群）
  4. TODO 标记完成 + 章节状态更新
  5. 清理临时文件
- **边界**：v7 只做整合传递，**不撰写内容**
