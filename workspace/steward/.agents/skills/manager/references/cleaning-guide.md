# 知识库清理指南

> 定期清理 wiki 中的冗余、过时内容。

---

## 一、清理的本质

知识库不是越积越多的仓库，而是**需要定期修剪的花园**。冗余内容会稀释关键信息的可信度，过时内容会误导判断。

清理的目标是：让 wiki 只保留真正需要长期保留的知识，而不是项目过程文件。

---

## 二、清理原则

### 禁止重复

- **Wiki 中的项目文件**：删除，保留在仓库
- **多个相似的规范页**：合并或删除
- **过时的版本记录**：归档或删除

重复是最大的浪费。项目文件应该在项目中管理，不应该出现在 wiki 里。

### 及时归档

- **已完成的项目**：从 entities/ 移出或删除
- **过期的规范**：更新或标记为废弃
- **无用的临时文件**：直接删除

### 保持更新

- **规范页面**：技能/SKILL 变更后同步更新
- **实体页面**：人员/系统变更后同步更新
- **索引页面**：目录结构变更后同步更新

---

## 三、清理操作

### 第一步：诊断现状

```bash
# 查看 wiki 状态
openclaw wiki status

# 列出所有页面
ls ~/.openclaw/wiki/concepts/
ls ~/.openclaw/wiki/entities/
ls ~/.openclaw/wiki/sources/
```

### 第二步：识别问题

| 问题类型 | 检查方法 |
|----------|----------|
| 冗余 sources | 是否包含项目文件（非工具文档） |
| 过时内容 | 上次更新时间是否超过 3 个月 |
| 缺失索引 | 是否有未记录的页面 |

### 第三步：执行清理

```bash
# 删除冗余文件
rm ~/.openclaw/wiki/sources/学生论文修改.md

# 移动错误放置的文件
mv /path/to/file ~/.openclaw/wiki/sources/

# 更新过期页面
openclaw wiki lint
```

---

## 四、每月检查清单

- [ ] sources/ 是否有项目文件（应只有工具文档）
- [ ] concepts/ 规范是否与 SKILL 同步
- [ ] entities/ 是否有过期人员/系统
- [ ] reports/ 是否有冗余仪表盘
- [ ] 无未分类的零散文件

---

## 五、常见问题处理

| 问题 | 解决方案 |
|------|----------|
| 项目文件误入 wiki | 删除，保留在仓库 |
| 规范与 SKILL 不同步 | 更新 wiki 或删除 wiki 引用 |
| 多个相似页面 | 合并或保留最完整的 |
| 页面内容为空 | 删除或补充内容 |
