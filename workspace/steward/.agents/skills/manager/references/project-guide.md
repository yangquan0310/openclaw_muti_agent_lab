# 通用项目管理指南

> 当用户需要整理/管理/初始化一个**未明确类型**的项目时使用。作为兜底方案。

---

## 一、通用项目的本质

通用项目是**没有明确类型的项目**的收容方案。当一个项目既不是论文、也不是课程、也不是程序时，用通用项目管理。

能明确类型的项目，应该优先使用 thesis-guide、course-guide 或 program-guide。通用指南是最后的选择，不是默认选项。

---

## 二、触发条件

| 场景 | 说明 |
|------|------|
| 用户说"整理项目"但未指定类型 | 需要先识别项目类型 |
| 用户要求初始化一个未知项目 | 建立基本结构 |
| 不适合 thesis/course/program-guide 时 | 作为兜底方案 |

---

## 三、标准目录结构

```
项目根目录/
├── README.md              # 项目总览（必须根目录）
├── AGENTS.md            # 项目操作手册（必须根目录）
├── TODO.md                # 任务看板（必须根目录）
├── metadata.json          # 机器可读配置（必须根目录）
│
├── uploads/              # 上传的原始文档
│   └── markdown/          # 解析后的 markdown 文件
│
├── manuscripts/           # 手稿/草稿文件
├── temp/                  # 临时文件
│
└── .agents/              # 代理配置
    └── agents/            # 角色规范文件
```

**四个契约文件**必须在根目录，缺一不可。

---

## 四、契约文件

| 文件 | 用途 |
|------|------|
| README.md | 项目总览、目标、参与人员 |
| AGENTS.md | 本项目专用的操作手册 |
| TODO.md | 任务看板、进度追踪 |
| metadata.json | 机器可读的项目元数据 |

---

## 五、保护文件规则

以下文件在任何位置都**不可移动**：

- README.md
- AGENTS.md
- TODO.md
- metadata.json
- .agentignore
- .gitignore

---

## 六、整理流程

**第一步：识别类型**。先判断项目是否真的无法归类于 thesis/course/program，如果能归类就用对应指南。

**第二步：检查现状**。查看当前目录结构、文件分布。

**第三步：确认需求**。向用户确认："这个项目是什么类型的？""有哪些特殊文件需要保护？"

**第四步：执行整理**。创建标准目录、按规则移动文件、更新 metadata.json。

**第五步：验证结果**。检查四个契约文件是否在根目录。

**第六步：汇报用户**。输出整理摘要。
