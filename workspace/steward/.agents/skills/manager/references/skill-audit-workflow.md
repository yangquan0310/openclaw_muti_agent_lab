# 技能审核工作流

> 当需要进行技能审计、核查技能质量时激活。

---

## 技能审计标准

### SKILL.md 五章节结构

| 章节 | 必须内容 |
|------|----------|
| name | 技能唯一标识 |
| description | 触发条件（何时激活、何时不用） |
| 核心原则 | 3-5 条核心信念 |
| 场景索引 | 指南文件与用途对应 |
| 边界条件 | 不做什么 |

### references/ 命名规范（固定命名）

| 类型 | 命名规则 |
|------|----------|
| 方法论指南 | `*-guide.md` |
| 标准规范 | `*-standards.md` |
| 工作流 | `*-workflow.md` |
| **核心工作流（固定）** | **`workflows.md`** |

### 自检问题

| 问题 | 是好技能吗 |
|------|----------|
| 能一句话说明这个技能做什么吗？ | 否 → 重写触发条件 |
| 能说清楚这个技能不做什么吗？ | 否 → 补边界条件 |
| 使用者能判断什么时候该用吗？ | 否 → 触发条件不够具体 |
| 每次使用会产生相同的结果吗？ | 否 → 步骤不稳定，不应固化 |

---

## 技能审计流程

1. **制定审计标准** — 基于 SKILL.md 五章节结构 + 命名规范
2. **检查目录结构** — 验证 SKILL.md、references/、assets/ 是否完整
3. **修复问题** — 补充章节、重命名文件、更新引用
4. **重建索引** — 运行 indexer.py 更新 manifest.json
5. **输出报告** — 将审计结果写入 wiki/syntheses/

---

## 常见问题修复

| 问题 | 修复方式 |
|------|----------|
| description 触发条件模糊 | 补充具体触发词 + 不激活场景 |
| 缺少边界条件 | 补充"不做什么" |
| references 文件名不规范 | 按命名规范重命名 |
| 版本号混乱 | 统一 SKILL.md 与 _meta.json |
| CLI 与实际不符 | 更新 SKILL.md 快速调用 |
