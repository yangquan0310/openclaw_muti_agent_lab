# 论文管理指南

> 当用户提到"论文"、"博士论文"、"期刊论文"、"学生论文"、"thesis"、"dissertation"或要求整理/管理论文写作项目时，使用本指南。

---

## 一、论文项目的本质

论文项目是以**文档管理**为核心的工作流。大管家的职责是：维护目录结构、更新元数据、管理任务链路，让论文的每一次修改都有迹可循。

论文项目不生产内容，只管理内容的流动和存档。

---

## 二、适用项目类型

| 项目类型 | 示例 |
|----------|------|
| 博士论文 | 数字化存储与自传体记忆 |
| 期刊论文 | 跨期选择的年龄差异 |
| 学生论文修改 | 领悟社会支持对大学生社会排斥的影响 |
| 文献综述 | 自传体记忆基础研究 |

---

## 三、标准目录结构

```
论文项目/
├── README.md              # 项目总览（必须根目录）
├── HANDBOOK.md            # 项目操作手册（必须根目录）
├── TODO.md                # 任务看板（必须根目录）
├── metadata.json          # 机器可读配置（必须根目录）
│
├── uploads/              # 上传的原始文档
│   └── markdown/          # 解析后的 markdown 文件
│
├── manuscripts/          # 手稿/草稿文件
│   └── {标题}/
│       ├── {标题}_R0.md  # Round 0 原始版
│       └── {标题}_R*.md  # 后续修改版
│
├── knowledge/            # 论文知识库
│
├── retrieval_report/     # 检索报告
│
├── temp/                 # 临时文件
│
└── .agents/
    └── agents/           # 代理角色规范
```

**四个契约文件**（README.md、HANDBOOK.md、TODO.md、metadata.json）必须在根目录，缺一不可。

---

## 四、角色分工

| 角色 | 职责 | 边界 |
|------|------|------|
| **psychologist** | 理论深化、学术内容审核 | 不修改论文结构 |
| **writer** | 文字润色、结构优化 | 不提供理论观点 |
| **reviewer** | 质量把关、提出修改意见 | 不直接修改 |

每个角色有独立的 `.md` 文件定义其职责范围，子代理应先阅读自己的角色定义再开始工作。

---

## 五、整理流程

当用户要求整理论文项目时，按以下步骤执行：

**第一步：检查现状**。查看当前目录结构、文件分布，判断是否有特殊文件需要保护（如 Pandoc 编译文件）。

**第二步：识别类型**。判断是否需要保护特殊文件。

**第三步：确认需求**。拿捏不准时，向用户确认："这个项目有特殊文件需要保护吗？"

**第四步：执行整理**。创建标准目录、按规则移动文件、更新 metadata.json。

**第五步：验证结果**。检查四个契约文件是否在根目录，TODO.md 是否需要更新。

**第六步：汇报用户**。输出整理摘要。

---

## 六、需要确认的特殊场景

| 场景 | 行动 |
|------|------|
| 存在 Pandoc 项目 | 询问用户是否保护 |
| 存在修改清单 | 询问用户是否保留 |
| manuscripts/ 中有 README.md | 立即移回根目录 |
| 存在未知类型的文件 | 询问用户处理方式 |

## 七、协作规范

| 时机 | 行动 |
|------|------|
| 任务完成后 | 在群聊中艾特大管家汇报（禁止私信） |

| 需要写作助手修改 | 艾特写作助手 |
| 需要审稿助手审核 | 艾特审稿助手 |
