# 任务推进指南

> 通过文件传递推进任务

---

## 一、推进的本质

任务推进不是消息传递，而是**文件传递**。每个任务对应一个输出文件，文件完成了，任务就完成了。代理之间交接的不是口头说明，而是文件路径。

---

## 二、核心机制

```
领取用户任务
    ↓
阅读项目 README 了解分工
    ↓
完善 TODO 任务树（每个任务对应一个文件）
    ↓
用户审核 TODO 任务树
    ↓
按文件传递推进任务
```

---

## 三、核心原则

| 原则 | 说明 |
|------|------|
| **任务即文件** | TODO 中每个任务对应一个文件 |
| **完成即文件完成** | 任务完成 = 文件编写完成 |
| **传递即推进** | 文件传给下一个代理 = 任务交接 |

---

## 四、推进流程

### 第一步：领取用户任务

用户提出需求 → 识别为项目任务 → 明确任务范围、交付物、截止时间 → 确认执行方式（直接执行 / 派发子代理）

### 第二步：阅读项目文档

```
触发：进入项目目录 或 用户提到项目名
    ↓
读取 README.md → 了解项目目标、角色分工、当前状态
    ↓
读取 HANDBOOK.md → 了解流水线、目录规范
    ↓
读取 metadata.json → 确认项目版本
```

### 第三步：完善 TODO 任务树

触发：README 已读取且 TODO 存在。检查 TODO 完整性，有缺失任务或状态不准确时更新。

### 第四步：审核 TODO 任务树

⭐ 这是关键环节。向用户展示更新后的 TODO 任务树，等待确认。用户提出修改则返回步骤3，确认通过则进入步骤5。

### 第五步：按文件传递推进任务

每个任务对应一个输出文件。代理完成任务 → 写入文件 → 更新 TODO 状态（标注文件路径）→ 通知下一个代理。循环直到所有任务完成。

---

## 五、TODO 任务树规范

### 任务格式

| 字段 | 说明 |
|------|------|
| 任务ID | 唯一标识 |
| 任务描述 | 简短描述 |
| 负责人 | 代理/人员 |
| 输出文件 | **必须对应一个文件路径** |
| 状态 | pending / in_progress / completed / blocked |
| 依赖 | 前置任务（完成后才能开始） |

### 文件传递标注

```
[T001] 任务描述          → /path/to/output.md
[T002] 任务描述          → /path/to/output2.md
```

完成后在 TODO 中标注：
```
[T001] ✅ 已完成 → /path/to/output.md
```

---

## 六、任务状态

| 状态 | 含义 |
|------|------|
| pending | 待启动 |
| in_progress | 进行中 |
| completed | 已完成（文件已写入） |
| blocked | 阻塞 |
