# 程序管理指南

> 当用户提到"程序"、"代码"、"开发"、"插件"、"系统"、"工具"、"脚本"或要求整理/管理程序开发项目时，使用本指南。

---

## 一、程序项目的本质

程序项目是以**代码资产**为核心的工作流。大管家的职责是维护目录结构、管理版本归档、确保项目可维护性。

程序项目不编写代码，由专业的开发者、审查者等角色协作完成。

---

## 二、适用项目类型

| 项目类型 | 示例 |
|----------|------|
| OpenClaw 插件 | agent-self-development |
| 工具开发 | Zotero 文件管理 |
| 系统项目 | 科研实验室搭建 |
| 脚本工具 | 自动化脚本 |

---

## 三、标准目录结构

```
程序项目/
├── README.md              # 项目总览（必须根目录）
├── HANDBOOK.md            # 项目操作手册（必须根目录）
├── TODO.md                # 任务看板（必须根目录）
├── metadata.json          # 机器可读配置（必须根目录）
│
├── src/                  # 源代码
├── test/                 # 测试代码
├── docs/                 # 文档
├── logs/                 # 日志
├── uploads/              # 上传的原始文件
├── temp/                 # 临时文件
│
└── .agents/
    ├── skills/           # 技能定义
    └── agents/           # 代理角色规范
```

**四个契约文件**必须在根目录，缺一不可。

---

## 四、角色分工

| 角色 | 职责 | 边界 |
|------|------|------|
| **developer** | 代码开发、功能实现 | 不负责代码审查 |
| **reviewer** | 代码审查、质量把关 | 不直接修改代码 |

---

## 五、整理流程

当用户要求整理程序项目时，按以下步骤执行：

**第一步：检查现状**。查看当前目录结构、文件分布，检查 .gitignore 是否存在。

**第二步：识别类型**。判断属于插件/工具/系统中的哪一种。

**第三步：确认需求**。向用户确认："`.openclaw/` 是否需要迁移到 `.agents/`？"

**第四步：执行整理**。创建标准目录、归档旧版本到 `temp/draft/`、更新 metadata.json。

**第五步：验证结果**。检查四个契约文件是否在根目录，.gitignore 是否需要更新。

**第六步：汇报用户**。输出整理摘要。

---

## 六、需要确认的特殊场景

| 场景 | 行动 |
|------|------|
| 存在 .openclaw 旧目录 | 询问是否迁移到 .agents |
| 存在未分类的 .md 文件 | 询问是文档还是代码说明 |
| docs/ 中已有复杂结构 | 询问整理策略 |
| 项目已有版本控制 | 检查 .gitignore 是否需要更新 |
