# manager 使用指南

> 本文档供用户和代理参考，回答 manager 管理技能中的常见问题。

---

## 一、manager 是什么

manager 是大管家的唯一管理技能入口。所有管理场景——论文、课程、程序、知识库、任务派发——都通过 manager 处理。

**manager 的定位**：管方向、定边界、分配任务、授权执行。不是执行者，而是协调者。

---

## 二、触发条件

当用户提到以下场景时，manager 自动接管：

| 场景 | 触发关键词 |
|------|------------|
| 任务管理 | 推进任务、完善TODO、任务管理、领取任务 |
| 论文项目 | 论文、博士论文、期刊论文、学生论文 |
| 课程项目 | 课程、备课、课件、教学、章节、教案、ppt |
| 程序项目 | 程序、代码、开发、插件、系统、工具、脚本 |
| 通用项目 | 整理项目、管理项目、创建新项目（未明确类型） |
| 知识库 | 知识库管理、wiki维护、整理wiki、清理知识库 |
| 任务派发 | 派任务、分配任务、通知XX做XX |

## 四、核心流程

```
领取任务 → 明确约束 → 更新TODO.md → 派发子代理 → 追踪进度 → 汇报老板
```

## 七、常见问题

**Q1：manager 和 task-dispatcher 有什么区别？**

manager 是管理技能唯一入口，涵盖所有管理场景。task-dispatcher 是专门给代理派发任务的子功能。日常使用中，manager 会根据场景自动路由到对应功能，不需要手动选择。

**Q2：如何新建一个项目？**

1. 确定项目类型（论文/课程/程序/通用）
2. 使用对应技能的初始化流程
3. 创建标准目录结构
4. 填写四个契约文件（README.md、HANDBOOK.md、TODO.md、metadata.json）

**Q3：项目整理怎么做？**

参考 organize-workflow.md：
1. 检查项目现状
2. 识别项目类型
3. 向用户确认特殊文件
4. 执行整理
5. 验证结果
6. 汇报用户

**Q4：四个契约文件是什么？**

README.md（项目总览）、HANDBOOK.md（操作手册）、TODO.md（任务看板）、metadata.json（机器可读配置）。这四个文件必须在项目根目录，不可移动。
