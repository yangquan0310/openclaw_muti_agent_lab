# .openclaw 体检指南

> 定期检查 OpenClaw 系统健康状态，确保稳定运行。
> 版本：v1.0.0 | 更新：2026-05-25 | 负责人：大管家

## 一、体检频率

| 场景 | 频率 | 触发条件 |
|------|------|----------|
| 常规体检 | **每周一次** | 每周一上午检查 |
| 版本更新后 | **立即检查** | `openclaw update` 后 |
| 异常后检查 | **按需** | 收到崩溃/报错通知时 |
| 重要任务前 | **提前一天** | 论文提交/备课等关键节点 |

## 二、体检项目清单（按优先级）

### P0 — 核心层（不可跳过）

#### 2.1 服务状态检查

```bash
openclaw status
```

**检查项：**
- Gateway 状态：`running` ✅ / `stopped` ❌
- 活跃会话数：正常 ≤ 20
- 插件加载：enabled 数量与预期一致

```bash
# 检查 systemd 服务（如果用 systemd 部署）
systemctl status openclaw
```

#### 2.2 配置文件完整性

```bash
# 核心配置文件
ls -la ~/.openclaw/openclaw.json
ls -la ~/.openclaw/openclaw.json.bak*
ls -la ~/.openclaw/openclaw.json.last-good

# 敏感配置文件
cat ~/.openclaw/.env | grep -v "KEY\|SECRET\|PASSWORD" | head -5  # 验证存在性
```

**检查项：**
- `openclaw.json` 存在且 ≥ 15KB
- 备份文件数量 ≤ 5 个（超量需清理）
- `.env` 存在且包含关键变量（DEEPSEEK/MINIMOX 等）

#### 2.3 定时任务检查

```bash
openclaw cron list
```

**检查项：**
- 活跃定时任务数量与预期一致
- 最近执行时间无异常堆积
- 失败任务立即重试或标记

### P1 — 运行数据层

#### 2.4 记忆数据库（sqlite）健康

```bash
# 检查数据库文件
ls -lh ~/.openclaw/memory/*.sqlite

# 检查 WAL 模式是否正常（无 -shm/-wal 堆积）
ls ~/.openclaw/memory/*.sqlite-wal 2>/dev/null | wc -l
```

**各数据库大小参考（正常范围）：**

| Agent | 数据库 | 正常大小 | 告警阈值 |
|-------|--------|----------|----------|
| steward | steward.sqlite | 40-50MB | > 100MB |
| programmer | programmer.sqlite | 30-40MB | > 80MB |
| psychologist | psychologist.sqlite | 35-40MB | > 80MB |
| mathematician | mathematician.sqlite | 18-20MB | > 40MB |
| physicist | physicist.sqlite | 14-16MB | > 35MB |
| instructor | instructor.sqlite | 20-22MB | > 45MB |

**WAL 堆积处理：**
```bash
# 如果 WAL 文件持续存在，执行 checkpoint
sqlite3 ~/.openclaw/memory/steward.sqlite "PRAGMA wal_checkpoint(TRUNCATE);"
```

#### 2.5 磁盘空间检查

```bash
df -h /root/.openclaw
du -sh /root/.openclaw/*/ | sort -rh | head -10
```

**告警阈值：**
- 根分区使用 > 80%
- 单个 subfolder > 500MB 需审查内容

#### 2.6 日志健康

```bash
# 最近的错误日志
tail -100 ~/.openclaw/logs/main.jsonl | grep -i "error\|exception\|fail" | tail -20

# Gateway 重启记录
tail -50 ~/.openclaw/logs/gateway-restart.log 2>/dev/null | tail -20
```

**检查项：**
- 无未处理的 ERROR
- Gateway 重启次数 ≤ 1 次/天
- 稳定性评分日志正常

### P2 — 功能插件层

#### 2.7 插件可用性

```bash
openclaw plugins list | grep -E "enabled|disabled" | head -20
```

**当前启用的插件：**
- `active-memory` — 活跃记忆
- `browser` — 浏览器控制
- `deepseek` — DeepSeek 模型
- `document-extract` — 文档提取
- `exa` — 搜索

**检查项：**
- 启用的插件均为预期插件
- 无新增未知插件突然启用

#### 2.8 技能完整性

```bash
ls ~/.openclaw/skills/
ls ~/.openclaw/plugin-skills/
```

**系统技能（~48个）：**
- Lark 系列（lark-*）：飞书全家桶
- 其他技能：zotero、tencent-*、pdf-generator 等

**检查项：**
- 技能目录数量与上次一致
- 无孤立/损坏的技能链接

### P3 — 安全与备份层

#### 2.9 Git 状态

```bash
cd ~/.openclaw && git status --short | head -10
```

**检查项：**
- 无未提交的修改
- 推送状态正常

#### 2.10 凭证文件

```bash
ls -la ~/.openclaw/credentials/
```

**检查项：**
- `lark.secrets.json` 存在
- 各 Agent 的 `allowFrom.json` 存在
- 无新增未知凭证文件

#### 2.11 API Key 有效性（按需）

```bash
# DeepSeek 可用性
curl -s https://api.deepseek.com/models -H "Authorization: Bearer $DEEPSEEK_API_KEY" | head -3
```

## 五、常见问题处理

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| 数据库过大 | sqlite > 100MB | 执行 `VACUUM` 压缩 |
| WAL 堆积 | -wal 文件持续增长 | `PRAGMA wal_checkpoint(TRUNCATE)` |
| Gateway 无响应 | status 显示 stopped | `openclaw restart` |
| 磁盘空间不足 | df 显示 > 90% | 清理 memory、media、npm 目录 |
| 插件加载失败 | 某插件突然 disabled | `openclaw plugins list` 查看原因 |
| 备份过多 | bak 文件 > 5 个 | 手动删除旧备份 |
