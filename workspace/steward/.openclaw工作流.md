## 二、日常维护工作流

### 2.1 每周维护（周一执行）

```
触发条件：每周一 09:00 或手动触发
执行脚本：见体检指南
预计耗时：10 分钟
```

**步骤：**
1. 运行 `openclaw status` 检查服务状态
2. 运行体检清单（P0 → P1 → P2 → P3）
3. 清理过大的 sqlite 数据库（WAL checkpoint + VACUUM）
4. 检查 git 状态，有变更则 commit
5. 更新体检报告到 memory/

### 2.2 版本更新工作流

```
触发条件：openclaw update 可用时
预计耗时：20 分钟
风险等级：中高
```

**步骤：**
```
[1] 更新前备份（必须）
    ├── cp openclaw.json openclaw.json.bak.$(date +%m%d)
    ├── cp openclaw.json openclaw.json.last-good
    └── 记录当前版本：openclaw --version

[2] 执行更新
    └── openclaw update

[3] 更新后检查
    ├── openclaw status
    ├── openclaw plugins list | grep enabled
    └── openclaw gateway restart

[4] 功能验证（按顺序）
    ├── 发送测试消息到飞书
    ├── 检查记忆系统
    └── 验证定时任务

[5] 确认正常后
    ├── 更新 README.md 版本号
    └── git add + commit + push
```

### 2.3 配置文件修改工作流

```
触发条件：修改 openclaw.json 或其他配置
风险等级：高
```

**步骤：**
```
[1] 修改前备份
    └── cp openclaw.json openclaw.json.bak.$(date +%m%d)

[2] 使用官方工具修改
    ├── openclaw config get <key>
    ├── openclaw config set <key> <value>
    └── openclaw config patch <json>
    ⚠️ 禁止直接用 exec/cat/echo 修改配置文件

[3] 验证配置
    └── openclaw config list | grep <key>

[4] 测试功能
    └── 重启 Gateway：openclaw gateway restart

[5] 确认正常后提交
    └── git add openclaw.json && git commit -m "config: <描述>"
```

## 三、问题处理工作流

### 3.1 服务异常处理

```
症状：Gateway 无响应 / 报 Error / 插件加载失败
```

**处理流程：**

```
Step 1: 收集信息（2分钟）
    ├── openclaw status
    ├── tail -50 logs/main.jsonl | grep ERROR
    └── tail -20 logs/gateway-restart.log

Step 2: 分类处理

    情况A：Gateway 进程停止
        → openclaw restart
        → 验证：openclaw status

    情况B：插件加载失败
        → openclaw plugins list | grep -i error
        → 单独禁用/启用该插件
        → openclaw gateway restart

    情况C：配置文件损坏
        → cp openclaw.json.bak openclaw.json
        → openclaw gateway restart
        → 或回退到 last-good

Step 3: 确认恢复
    → 向飞书发送测试消息
    → 确认各 Agent 正常响应
```

### 3.2 数据库异常处理

```
症状：sqlite 文件过大 / WAL 堆积 / 查询超时
```

**处理流程：**
```bash
# Step 1: 诊断
ls -lh memory/*.sqlite
ls memory/*.sqlite-wal  # 检查 WAL

# Step 2: WAL 检查点（不丢失数据）
for db in memory/*.sqlite; do
    sqlite3 "$db" "PRAGMA wal_checkpoint(TRUNCATE);"
done

# Step 3: 压缩（可选，文件过大时）
for db in memory/*.sqlite; do
    sqlite3 "$db" "VACUUM;"
done

# Step 4: 验证
ls -lh memory/*.sqlite
```

### 3.3 磁盘空间不足处理

```
触发：df 显示任一分区 > 85%
```

**清理优先级（从高到低）：**

| 优先级 | 目录 | 清理方式 | 风险 |
|--------|------|----------|------|
| 1 | `media/` | 删除超过 30 天的缓存文件 | 低 |
| 2 | `npm/` | `pnpm store prune` | 低 |
| 3 | `memory/` | VACUUM 压缩 | 低 |
| 4 | `logs/` | 删除 30 天前日志 | 低 |
| 5 | `agents/` | 归档超过 60 天会话 | 中 |
| 6 | `browser-existing-session/` | 清理旧会话 | 中 |
| 7 | `wiki/` | wiki-cleanup 技能 | 中 |

## 四、Git 管理工作流

### 4.1 分支策略

```
main     — 稳定版本，只接受已验证的推送
development — 开发分支，日常提交
```

### 4.2 提交流局

```
[1] 提交前检查
    ├── git status — 无敏感信息泄露
    ├── .env 不在提交列表中
    └── openclaw status 正常

[2] 提交格式
    git add <files>
    git commit -m "type(scope): 描述"
    # type: config/feat/fix/doc/cleanup

[3] 推送到 development
    git push origin development

[4] 合并到 main
    # 仅在重大版本/体检完成后执行
    git checkout main
    git merge development
    git push origin main
```

### 4.3 敏感信息规则

```
禁止提交：
    - .env（包含所有 API Key）
    - credentials/*.json（包含 secrets）
    - state/（运行时状态）

允许提交：
    - openclaw.json（不含 secrets）
    - README.md
    - skills/（技能代码）
    - plugin-skills/（软链接）
```

## 五、备份策略

### 5.1 备份清单

| 文件/目录 | 备份频率 | 保留数量 | 位置 |
|-----------|----------|----------|------|
| `openclaw.json` | 手动+版本更新前 | 5 | 本地 + Git |
| `memory/*.sqlite` | 每周 | 2（周备份） | 本地 |
| `.env` | 每次修改后 | 3 | 仅本地 |
| `credentials/` | 每月 | 2（月备份） | 本地 |

### 5.2 备份脚本（建议 cron）

```bash
# 每周一 02:00 执行
BACKUP_DIR=/root/data/disk/仓库/openclaw-backup
DATE=$(date +%Y%m%d)

# 备份配置文件
mkdir -p $BACKUP_DIR/$DATE
cp ~/.openclaw/openclaw.json $BACKUP_DIR/$DATE/
cp -r ~/.openclaw/credentials/ $BACKUP_DIR/$DATE/

# 清理 30 天前备份
find $BACKUP_DIR -maxdepth 1 -type d -mtime +30 -exec rm -rf {} \;
```
