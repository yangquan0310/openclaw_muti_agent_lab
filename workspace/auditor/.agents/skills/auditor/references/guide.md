# 使用指南

> 如何使用 auditor 技能进行有效的教学审核

---

## 审核流程

```
┌─────────────────────────────────────────────────────────────┐
│  1. 接收交付物                                              │
│     ↓                                                       │
│  2. 对照四要素检查清单（consistency-checklist.md）           │
│     ↓                                                       │
│  3. 逐项核查并记录问题                                      │
│     ↓                                                       │
│  4. 判定问题等级（P0/P1/P2/P3）                             │
│     ↓                                                       │
│  5. 撰写结构化反馈（feedback-guide.md）                     │
│     ↓                                                       │
│  6. 提交审核报告                                            │
└─────────────────────────────────────────────────────────────┘
```

---

## 审核时机

| 时机 | 说明 |
|------|------|
| 课件脚本完成后 | 呈现师交付 v4/v5 版本后 |
| 教案定稿前 | 进入终稿教案阶段前 |
| PPT编译前 | 生成 PPTX 前 |

---

## 审核原则

### 四眼原则
以独立于创作者的身份审视产出，避免先入为主。

### 清单思维
使用检查清单逐项核查，不凭感觉判断。

### 具体优先
模糊的"不够好"不如精确的"第3页目标与内容不匹配"。

### 闭环追踪
提出问题后跟踪修改，确保问题被解决。

---

## 问题等级定义

| 等级 | 说明 | 处理方式 |
|------|------|----------|
| P0 | 重大错误，内容偏离 | 必须修复，否则不能通过 |
| P1 | 重要问题，需要修改 | 强烈建议修复 |
| P2 | 次要问题，可协商修改 | 建议修复 |
| P3 | 优化建议，可选 | 保留意见 |

---

## 输出格式

审核意见应包含：

1. **问题列表**：编号、位置、问题描述、问题等级、修改建议
2. **整体评价**：对交付物的总体判断
3. **修改优先级**：明确 P0 必须修复才能进入下一阶段

详见 [feedback-guide.md](feedback-guide.md)
