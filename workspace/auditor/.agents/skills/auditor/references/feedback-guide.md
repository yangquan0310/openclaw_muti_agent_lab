# 反馈撰写指南

> 结构化审核意见的撰写规范

---

## 反馈基本原则

1. **具体优先**：模糊的"不够好"不如精确的"第3页目标与内容不匹配"
2. **建设性批评**：不仅说"哪里不对"，更要说"怎么改"
3. **对事不对人**：指出问题而非指责作者
4. **分级清晰**：P0/P1/P2/P3 问题明确区分

---

## 反馈结构

```
┌─────────────────────────────────────────────────────────────┐
│  审核摘要                                                    │
│  - 审核对象：                                                │
│  - 审核时间：                                                │
│  - 审核结论：□ 通过  □ 修改后通过  □ 不通过                 │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  问题列表（按优先级排序）                                    │
│  P0 问题（必须修复）：                                       │
│  P1 问题（强烈建议修复）：                                   │
│  P2 问题（建议修复）：                                       │
│  P3 问题（可选优化）：                                       │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  问题详情                                                    │
│  | 序号 | 位置 | 类型 | 问题描述 | 修改建议 |               │
│  |------|------|------|----------|----------|               │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  整体评价                                                    │
│  - 优点：                                                    │
│  - 需改进：                                                  │
│  - 修改优先级：                                              │
└─────────────────────────────────────────────────────────────┘
```

## 反馈用语规范

### 指出问题
| ❌ 避免 | ✅ 推荐 |
|----------|----------|
| "这是错的" | "这里与教材定义不一致" |
| "太糟糕了" | "建议优化表述" |
| "你怎么这样写" | "建议调整为..." |

### 肯定优点
| 用语 | 场景 |
|------|------|
| "逻辑清晰" | 结构合理时 |
| "表述准确" | 概念正确时 |
| "详略得当" | 内容取舍合理时 |
| "创新之处" | 有亮点时 |

---

## 审核结论判定

| 结论 | 条件 |
|------|------|
| 通过 | 无 P0、P1 问题 |
| 修改后通过 | 有 P1 问题但有明确修复计划 |
| 不通过 | 有 P0 问题 |

---

## 反馈文件命名

```
{审核对象}_{版本}_审核意见.md

示例：
ch10_v5_审核意见.md
ch11_行动研究法_审核意见.md
```

---

## 反馈交付流程

1. 撰写审核意见文档
2. 标注问题等级和位置
3. 明确修改建议
4. 给出审核结论
5. 提交审核报告
