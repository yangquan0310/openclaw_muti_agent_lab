# 质量标准

> 什么样的技能算好技能。

---

## 核心标准

### 有明确的触发条件

- 触发条件是具体的，不是模糊的
- 一个新问题出现时，能判断出是否应该用这个技能
- 不会和其他技能的触发条件冲突或重叠
- description 符合渐进式披露原则：说清楚何时激活、何时不用（详见 [progressive-disclosure.md](progressive-disclosure.md) L1 层设计）

### 有清晰的边界

- 能说清楚这个技能不做什么
- 边界不会随着使用不断扩大
- 边界不会在两个技能之间形成灰色地带

### 结构服务于目的

- SKILL.md 简洁，只放必要信息（L2 层）
- references/ 按需加载，不过度设计（L3 层）
- scripts/ 只放被重复使用的工具
- 三层结构符合渐进式披露模型（详见 [progressive-disclosure.md](progressive-disclosure.md)）

### 可验证

- 有 selfcheck.py 或类似的自检工具
- 质量标准可被工具自动检查
- 每次更新后能快速验证是否仍然合格

---

## 不合格模式

| 模式 | 问题 |
|------|------|
| 万能技能 | 触发条件太宽，没有边界 |
| 一次性技能 | 建完就没用过，白费力气 |
| 膨胀技能 | 不断扩展，失去焦点 |
| 空洞技能 | 有结构但没有实际内容 |
| 重复技能 | 和现有技能高度重叠 |

---

## 自检问题

| 问题 | 是好技能吗 |
|------|------|
| 能一句话说明这个技能做什么吗？ | 否 → 重写触发条件 |
| 能说清楚这个技能不做什么吗？ | 否 → 补边界条件 |
| 使用者能判断什么时候该用吗？ | 否 → 触发条件不够具体 |
| 每次使用会产生相同的结果吗？ | 否 → 步骤不稳定，不应固化 |
