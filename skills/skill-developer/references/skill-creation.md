# 技能创建

> 什么时候应该创建一个新技能，什么时候不应该。

---

## 判断框架

### 应该创建新技能

| 条件 | 说明 |
|------|------|
| **同类任务重复三次以上** | 第一次试错，第二次确认模式，第三次固化 |
| **用户明确要求** | 用户说"创建一个技能"时直接开始 |
| **现有技能无法覆盖** | 边界明确不同，无法通过扩展解决 |
| **模式已稳定** | 步骤、参数、判断逻辑已固定 |

### 不应该创建新技能

| 条件 | 说明 |
|------|------|
| **第一次做某类任务** | 还没形成方法论，先试跑 |
| **已有技能可以扩展** | 先检查是否能扩展而非新建 |
| **用户明确说"简单查一下"** | 轻量查询不需要固化 |
| **一次性任务** | 不重复的工作不值得固化 |
| **还没想清楚边界** | 约束不清晰时建技能会建错 |

---

## 触发判断树

```
同类任务做过两次以上？
├── 否 → 不建，先用现有工具
└── 是 → 用户明确要求建技能？
         ├── 是 → 建
         └── 否 → 现有技能能扩展？
                  ├── 是 → 扩展而非新建
                  └── 否 → 模式稳定吗？
                           ├── 是 → 建
                           └── 否 → 等一等，再跑两次再判断
```

---

## 新建与扩展的选择

| 场景 | 决策 |
|------|------|
| 触发条件重叠 | 扩展优于新建 |
| 目的相同但步骤不同 | 扩展，在原技能内增加分支 |
| 目的完全不同 | 新建 |
| 共享工具/脚本 | 通过共享 scripts 而非新建技能解决 |

---

## 常见错误

- **过早创建**：只做了一次就开始建技能，模式还没稳定
- **过晚创建**：做了五六次重复才想起来建，浪费了
- **新建癖**：不管什么情况都想新建，忽视扩展
