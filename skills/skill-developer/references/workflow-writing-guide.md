# 如何撰写工作流

> 本章讲述如何撰写 references 中的工作流类文章（`*-workflow.md`）。

---

## 工作流的定位

工作流回答：**按什么顺序做？**

给出具体的执行步骤，阶段划分清晰，决策点明确。

---

## 写作要点

### 1. 阶段划分清晰

每个阶段有明确的**输入**和**输出**。

```markdown
## 阶段 1：{阶段名称}

**输入**：{进入此阶段前需要什么}
**输出**：{完成此阶段后产出什么}

### 步骤 1.1：{具体步骤}
```

### 2. 给出具体命令

每个步骤都有**可执行**的命令。

```
❌ 不好：
### 步骤 1：初始化技能

✅ 好：
### 步骤 1：初始化技能

python3 scripts/init.py <skill-name> <description>
```

### 3. 决策点标注

在工作流分叉的地方，要明确标注**判断条件**和**走哪条路**。

```markdown
### 判断：如果需要命令行入口
→ 创建 scripts/main.py

### 判断：如果不需要
→ 跳过 scripts/ 目录
```

### 4. 可重复执行

工作流应该可以**幂等执行**。

---

## 开发工作流

### 阶段 1：明确约束

**输入**：需求描述
**输出**：SKILL.md 的触发条件、_meta.json 的 description

**必答问题**：
- 这个技能解决什么问题？
- 触发条件是什么？
- 边界在哪里（能做什么/不能做什么）？

---

### 阶段 2：设计结构

**输入**：约束定义
**输出**：目录结构

**根据目的选择**：
- 需要 CLI 入口吗？→ 需要 scripts/main.py
- 需要面向对象吗？→ 创建 scripts/{模块}/
- 需要 MCP 暴露吗？→ 创建 mcp/server.py

**原则**：结构由目的决定，不写死。

---

### 阶段 3：实现方法

**输入**：结构设计
**输出**：scripts/ 中的方法

```python
#!/usr/bin/env python3
def do_something(param: str) -> dict:
    """执行某个操作"""
    return {"success": True, "result": param}
```

---

### 阶段 4：MCP 暴露

**输入**：方法实现
**输出**：mcp/server.py 中注册的工具

```python
EXPOSED_TOOLS = [
    {
        "name": "{skill}_do_something",
        "description": "执行某个操作",
        "parameters": {...}
    }
]
```

---

### 阶段 5：撰写指南

**输入**：结构设计、方法实现
**输出**：references/ 中的指南

- `guide.md` — 使用指南
- `index.md` — 索引

**原则**：指南回答问题，不是复述结构。

---

### 阶段 6：自检与迭代

**输入**：完整技能
**输出**：自检通过 / Git 提交

```bash
python3 scripts/selfcheck.py /path/to/skill
```

**自检不通过？** → 修复 → 再次自检 → 通过后 Git 提交

---

## 更新工作流

### 判断变更范围

| 范围 | 适用场景 |
|------|----------|
| **小改动** | 修复错误、更新文档、调整参数（改1个文件） |
| **中改动** | 新增方法、修改结构、新增指南（改2-3个文件） |
| **大改动** | 重构核心逻辑、变更触发条件、版本升级（涉及多模块） |

---

### 执行更新

**更新 SKILL.md**：
```markdown
## 版本历史

| 版本 | 日期 | 更新 |
|------|------|------|
| x.x.x | 2026-05-20 | 更新内容描述 |
```

**更新 _meta.json**：
```json
{
    "version": "x.x.x"
}
```

**更新代码**：
- 在 scripts/ 中添加或修改方法
- 在 mcp/server.py 中更新 EXPOSED_TOOLS

**更新指南**：
- 在 references/ 中新增或修改指南
- 更新 index.md 导航

---

### 自检

```bash
python3 scripts/selfcheck.py /path/to/skill
```

---

### Git 提交

```bash
git add .
git commit -m "更新 {技能名}：{更新内容}"
```

---

## 版本号规范

| 类型 | 规则 | 示例 |
|------|------|------|
| **大版本** | 不兼容的重大变更 | 1.0.0 → 2.0.0 |
| **小版本** | 向下兼容的功能新增 | 1.0.0 → 1.1.0 |
| **补丁** | bug 修复 | 1.0.0 → 1.0.1 |

## 反面案例

### 步骤太模糊

```
❌ 不好：
## 阶段 1：初始化

### 步骤 1：创建文件
### 步骤 2：写内容
```

### 缺少决策点

```
❌ 不好：
## 开发流程

### 第一步：写代码
### 第二步：测试
### 第三步：发布
```

---

## 本章小结

1. **阶段划分**：每个阶段有输入和输出
2. **具体命令**：每个步骤可执行
3. **决策点标注**：分叉处有判断条件
4. **可重复执行**：幂等设计
