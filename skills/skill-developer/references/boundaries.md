# 边界约束

> 什么不能做，什么应该避免。

---

## 禁止事项

| 禁止 | 原因 |
|------|------|
| **禁止擅自定义 scripts/ 结构** | scripts/ 结构取决于代理目的，不可强制要求特定结构 |
| **禁止没有 CLI 入口** | 所有技能必须提供 `{技能名} {模块名} {方法名}` 三段式格式的 CLI |
| **禁止触发条件为空或模糊** | 无法判断什么时候该用，就等于没有触发条件 |
| **禁止 SKILL.md 臃肿** | SKILL.md 应该简洁，深度内容放到 references/ |
| **禁止硬编码路径** | 使用相对路径或环境变量，不写死绝对路径 |

---

## 避免事项

| 避免 | 原因 |
|------|------|
| **避免过度工程** | 不要为了规范而规范，业务需求优先 |
| **避免重复造轮子** | 先查现有工具/技能，再决定是否新建 |
| **避免功能蔓延** | 每个技能聚焦一个目的，不贪多 |
| **避免跳过自检** | selfcheck.py 是最后防线，不要跳过 |
| **避免没有版本历史** | 不记录版本变化，后续维护困难 |

---

## 边界模糊时的处理

| 情况 | 处理 |
|------|------|
| 不确定该不该加一个功能 | 不加，先跑几次再判断 |
| 不确定该新建还是扩展 | 优先扩展，除非边界明显不同 |
| 不确定该放哪个文件 | 放更接近目的的那个 |
| 不确定该用什么命名 | 查 naming.md，仍不确定就选更短的那个 |
