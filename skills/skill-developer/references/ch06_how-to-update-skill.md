# 如何更新技能

> 如何更新、迭代已发布的技能。

---

## 问题

### 什么时候需要更新？

| 场景 | 是否更新 |
|------|----------|
| 发现 bug 或缺陷 | ✅ 更新 |
| 需求变更，需要扩展功能 | ✅ 更新 |
| 用户提出新场景需要支持 | ✅ 更新 |
| 代码结构或性能可优化 | ✅ 更新（可选） |
| 只是用了一次 | ❌ 不需要更新 |

### 更新 vs 重构

| | 更新 | 重构 |
|---|---|---|
| **触发条件** | 功能 bug、需求变更 | 代码结构问题 |
| **范围** | 修改部分功能 | 可能是整个技能 |
| **风险** | 较低 | 较高 |
| **决策** | 直接执行 | 先评估影响 |

### 更新的风险

更新已有技能可能影响：
- 依赖此技能的其他技能
- 正在使用此技能的 cron 任务
- 用户的自动化脚本

**大版本更新（不兼容变更）需要格外谨慎。**

---

## 方法论

### 判断变更范围

| 范围 | 适用场景 | 影响 |
|------|----------|------|
| **小改动** | 修复错误、更新文档、调整参数 | 只影响 1 个文件 |
| **中改动** | 新增方法、修改结构、新增指南 | 影响 2-3 个文件 |
| **大改动** | 重构核心逻辑、变更触发条件、版本升级 | 影响多个模块 |

### 更新的决策原则

1. **向后兼容优先** — 新增功能不破坏现有调用方式
2. **小步快跑** — 宁可多次小更新，不要一次大更新
3. **自检后提交** — 每次更新都经过自检

---

## 工作流

### 步骤 1：评估变更范围

回答：
- 这次更新改几个文件？
- 是否影响现有调用方式？
- 是否需要告知用户？

### 步骤 2：执行更新

**更新 SKILL.md**：
```markdown
## 版本历史

| 版本 | 日期 | 更新 |
|------|------|------|
| x.x.x | 2026-05-25 | 更新内容描述 |
```

**更新 _meta.json**：
```json
{
    "version": "x.x.x"
}
```

**更新代码**：
- 在 `scripts/` 中添加或修改方法
- 在 `mcp/server.py` 中更新 `EXPOSED_TOOLS`

**更新 references**：
- 在现有章节中修改内容
- 或新增章节解决新问题
- 更新 `index.md` 导航

### 步骤 3：自检

```bash
python3 scripts/selfcheck.py /path/to/skill
```

### 步骤 4：Git 提交

```bash
git add .
git commit -m "更新 {技能名}：{更新内容}"
```

### 步骤 5：通知（如需要）

对于大版本更新或用户可见的变更，通知用户。

## 执行标准

### 版本号规范

| 变更类型 | 版本号规则 | 示例 |
|----------|------------|------|
| Bug 修复 | patch: 1.0.0 → 1.0.1 | |
| 新增功能（向下兼容） | minor: 1.0.0 → 1.1.0 | |
| 不兼容变更 | major: 1.0.0 → 2.0.0 | |

### 兼容性标准

| 标准 | 要求 |
|------|------|
| CLI 参数 | 不删除已有参数，不改变已有参数含义 |
| MCP 工具 | 不删除已有工具，不改变已有工具参数 |
| SKILL.md 触发条件 | 不缩小范围，只扩展 |

### 更新记录标准

| 标准 | 要求 |
|------|------|
| 版本历史 | 每次更新追加一条 |
| 更新内容 | 简洁描述改了什么 |
| 日期格式 | YYYY-MM-DD |

## 检查清单

### 更新前

- [ ] 确定变更范围（小/中/大）
- [ ] 评估对现有调用的影响
- [ ] 确认向后兼容

### 更新后

- [ ] SKILL.md 版本历史已更新
- [ ] _meta.json 版本号已更新
- [ ] 代码变更符合 [ch04_how-to-write-scripts.md](ch04_how-to-write-scripts.md) 标准
- [ ] references 章节已更新（如有）
- [ ] 自检脚本通过
- [ ] Git 提交

### 大版本更新额外检查

- [ ] 确认不兼容变更的必要性
- [ ] 准备好迁移文档
- [ ] 通知用户
