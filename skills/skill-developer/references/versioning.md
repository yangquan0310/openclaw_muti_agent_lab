# 版本管理

> 版本号规则和更新时机。

---

## 版本号格式

`major.minor.patch`

| 位置 | 说明 |
|------|------|
| major | 主版本，不兼容变更 |
| minor | 次版本，向下兼容的新功能 |
| patch | 补丁版本，bug 修复 |

---

## 判断标准

### patch：1.0.0 → 1.0.1

- bug 修复
- 文档修正
- 不影响任何外部行为的小改动

### minor：1.0.0 → 1.1.0

- 新增功能（向下兼容）
- 新增触发条件（原有触发条件不变）
- 新增 references 章节
- 优化内部结构（不影响使用方式）

### major：1.0.0 → 2.0.0

- 删除或重命名触发条件
- 改变 CLI 接口
- 改变 SKILL.md 的核心原则
- 不兼容的结构变更

---

## 更新时机

| 场景 | 版本号 |
|------|------|
| 修复一个错误 | patch +1 |
| 扩展触发条件 | minor +1 |
| 重构内部结构 | minor +1 |
| 改变 CLI 用法 | major +1 |
| 删除功能 | major +1 |

---

## 版本历史格式

每次更新在 SKILL.md 末尾追加：

```markdown
| 版本 | 日期 | 更新 |
|------|------|------|
| 1.2.0 | 2026-05-26 | 新增 xxx 章节 |
```

---

## 常见错误

- **从不更新版本号**：不知道什么时候该改
- **随意跳版本**：从 1.0.0 直接到 3.0.0
- **版本号膨胀**：每次改动都加 major
- **版本历史缺失**：改完不记录，无法追溯
