# 命名指南

> 本章讲述 references 中文章命名的思考框架，解释为什么这样命名，以及如何决定一个新文章应该叫什么名字。

---

## 为什么要命名

命名不是随意取的。好的命名让代理看到文件名就知道：
1. 这个文件是关于什么的
2. 应该用什么类型的内容来填充
3. 和其他文件有什么区别

---

## references 文章的三类命名

根据文章类型，references 中的文章有明确的命名规则：

| 类型 | 命名规则 | 原因 |
|------|----------|------|
| **方法论** | `*-guide` | guide = "如何做"的指南，解释方法 |
| **标准** | `*-standards` | standards = 必须遵守的规范 |
| **工作流** | `*-workflow` | workflow = 执行步骤的流程 |

---

## 如何判断一个文章应该用什么命名

### 判断流程

```
这个文章主要回答什么问题？
│
├─ "为什么要这样做？" → 方法论 → -guide
│
├─ "交付物要满足什么条件？" → 标准 → -standards
│
└─ "按什么顺序做？" → 工作流 → -workflow
```

### 示例

**场景1**：要为技能写一个"如何检查代码质量"的文章
- 问自己：这是告诉代理"为什么要做检查"还是"检查的步骤是什么"？
- 如果是解释原理 → -guide
- 如果是列出检查项 → -standards

**场景2**：要为技能写一个"版本管理"的文章
- 如果讲版本号规则 → -standards
- 如果讲发版流程 → -workflow

---

## 方法论 vs 标准：核心区别

| | 方法论（-guide） | 标准（-standards） |
|---|---|---|
| **回答的问题** | 为什么要这样做？ | 要满足什么条件？ |
| **内容特点** | 解释原理、给出框架 | 检查项、通过标准 |
| **语言风格** | 引导性："你应该考虑..." | 强制性："必须满足..." |

### 示例对比

**方法论：命名指南（本章）**
```
## 为什么要用 -guide / -standards / -workflow

因为文章回答的问题不同：
- 回答"为什么"→ 方法论
- 回答"是什么条件"→ 标准
- 回答"先做什么"→ 工作流
```

**标准：命名规范**
```
## 命名规则

| 类型 | 命名规则 |
|------|----------|
| 方法论 | 必须以 -guide 结尾 |
| 标准 | 必须以 -standards 结尾 |
| 工作流 | 必须以 -workflow 结尾 |
```

---

## 特殊文件名

有两个文件名是固定的，不适用上述规则：

| 文件名 | 用途 |
|--------|------|
| `index.md` | 书籍索引，导航页 |
| `guide.md` | 使用指南，介绍如何使用这个技能 |

---

## 检查清单

新建一个 references 文章时：

- [ ] 这个文章主要回答什么问题？
- [ ] 是解释原理（-guide）、规定条件（-standards）、还是描述流程（-workflow）？
- [ ] 文件名是否符合命名规范？
- [ ] 和已有的文章是否重复？

---

## 本章小结

1. **命名规则**：-guide / -standards / -workflow 对应三类文章
2. **判断方法**：看文章主要回答什么问题
3. **固定文件名**：index.md 和 guide.md 不适用上述规则
