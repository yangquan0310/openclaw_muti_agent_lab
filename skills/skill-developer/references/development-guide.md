# 技能开发指南

> 程序员实践技能沉淀的十条黄金法则，适用于所有技能开发场景。

---

## 核心十则

### 1. 先手动跑通
新类型任务先手工执行 3-10 次，跑通流程再动手写代码。

### 2. 进项目先看门牌
进项目后、开工前，必须先读取 `README.md`、`HANDBOOK.md`、`TODO.md`，确认理解规范后再执行，禁止凭记忆开工。

### 3. 改完即交
文件修改后回顾变更，git commit 到 development，信息写清改了什么。

### 4. 给我看结果
完成后展示输出，等用户确认是否满意。

### 5. 该自动就自动
周期性任务直接加 cron，不用每次问用户。

### 6. 固化反思
当一个问题出现两次以上，说明规范未固化，应将正确做法写入相关规范文件。

### 7. 满意就固化
确认满意后，用 `skill-developer` 写成可复用的个人技能。

### 8. 一事一技
同类工作只建一个技能，不重复造轮子。新建前先搜现有技能，能扩展就不新建。

### 9. 事不过二
同一件事让用户说两次，说明早该做成自动化技能了。

### 10. 六步成技
概念 → 手动跑 3-10 次 → 给用户审 → 用 `skill-developer` 固化 → 加 cron → 监控首跑迭代。

---

## 执行决策

| 情况 | 行动 |
|------|------|
| 指令以「查看」「显示」「列出」「读取」开头 | 直接执行，无需确认 |
| 指令是疑问句（什么是、为什么） | 直接执行，无需确认 |
| 用户明确说「简单查一下」「看一眼」 | 直接执行，无需确认 |
| Cron 定时任务消息 | 直接执行，无需确认 |
| 除此之外的一切 | 先确认再执行 |

---

## 安全红线

- **删除文件**：必须得到用户明确确认
- **配置操作**：对 `openclaw.json` 必须使用 `openclaw config get/set/patch`，禁止 exec/cat/echo/write 直接操作
- **回复 GitHub 备份**：必须得到用户确认
- **禁止泄露敏感信息**：不可泄露 `.env` 中的任何密钥、Token 等

---

*这些原则是程序员实践技能的结晶，应贯穿所有技能开发过程。*
