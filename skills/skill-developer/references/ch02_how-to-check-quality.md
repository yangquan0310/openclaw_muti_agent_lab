# 如何检查质量

> 技能交付前需要检查哪些项。

---

## 问题

### 为什么要质量检查？

技能是供代理在实际任务中使用的工具。如果质量不达标：
- 代理可能无法正确触发技能
- 运行时可能出错
- 可能泄露敏感信息

### 什么时候需要质量检查？

| 时机 | 检查内容 |
|------|----------|
| 开发完成后 | 完整检查所有项 |
| 更新后 | 只检查变更相关的项 |
| 上线前 | 确认所有项通过 |

### 自检命令

```bash
python3 scripts/selfcheck.py /path/to/skill
```

---

## 方法论

### 检查的三个层次

| 层次 | 检查内容 | 适用场景 |
|------|----------|----------|
| **结构** | 文件/目录是否存在 | 初始检查 |
| **内容** | 文件内容是否正确 | 深度检查 |
| **安全** | 是否有敏感信息泄露 | 必须检查 |

### 优先级

1. **必须通过**：结构错误 → 技能无法加载
2. **强烈建议**：内容错误 → 运行时可能出错
3. **一票否决**：安全问题 → 泄露敏感信息

## 工作流

### 执行自检

```bash
python3 scripts/selfcheck.py /path/to/skill
```

### 逐项检查

根据「执行标准」中的检查表逐项核对：

| 顺序 | 检查类别 | 对应检查项 |
|------|----------|------------|
| 1 | 结构检查 | 检查项 1-9 |
| 2 | 目录命名检查 | 检查项 10-11 |
| 3 | SKILL.md 检查 | 检查项 12-17 |
| 4 | 代码检查 | 检查项 18-24 |
| 5 | 安全检查 | 检查项 25-27 |
| 6 | MCP 检查 | 检查项 28-30 |
| 7 | references 检查 | 检查项 31-32 |

### 判断：是否通过

- **全部通过** → 可以交付
- **有未通过项** → 修复 → 重新自检

## 常见问题

### 问题：SKILL.md 触发条件写什么？

**触发条件**是代理判断何时使用此技能的条件。

| 好的触发条件 | 坏的触发条件 |
|--------------|--------------|
| "创建新技能" | "技能相关" |
| "修复 bug" | "代码问题" |
| "需要定时任务" | "自动化" |

### 问题：方法名怎么算"有具体含义"？

| 具体 | 不具体 |
|------|--------|
| `search()`, `validate()`, `calculate()` | `main()`, `do_something()`, `process()` |
| `init_skill()`, `create_file()` | `run()`, `execute()`, `handle()` |

### 问题：敏感信息包括哪些？

- API Key/Token（OpenAI、Google 等）
- 用户个人信息（手机号、邮箱、身份证）
- 数据库连接字符串
- 文件路径中的用户名
- 硬编码的密码
