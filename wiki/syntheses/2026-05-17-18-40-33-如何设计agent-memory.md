# Agent Memory 设计哲学与架构

> 本文档探讨 Agent Memory 的设计哲学、技术路线和各实现方案的对比。

## 一、设计哲学

### 1. memory-core
- **状态**：✅ enabled
- **Slot**：`slots.memory = memory-core`
- **存储**：`~/.openclaw/memory/{agent}.sqlite`
- **功能**：基础记忆读写，通过 `memory_search` / `memory_get` 工具访问
- **特点**：每个 Agent 独立 sqlite，dreaming 机制自动整理

### 2. memory-wiki
- **状态**：✅ enabled
- **存储**：`~/.openclaw/wiki/`
- **功能**：Obsidian 友好的知识库编译器
- **特点**：持久化 wiki，支持 `wiki_search` / `wiki_get` 工具

### 3. active-memory
- **状态**：❌ disabled
- **功能**：每次回复前启动记忆子代理，检索并注入相关记忆
- **特点**：最激进，token 开销大，当前未启用

## 二、第三方记忆插件

### TencentDB Agent Memory
- **来源**：Tencent 开源
- **存储**：`~/.openclaw/memory-tdai/`
- **架构**：L0 Conversation → L1 Atom → L2 Scenario → L3 Persona
- **特色**：Mermaid 符号化压缩、Context Offloading、token 降低 61%

## 三、冲突分析

| 维度 | 冲突情况 |
|------|----------|
| 存储路径 | 不冲突（sqlite vs memory-tdai） |
| Wiki 路径 | 不冲突（wiki vs memory-tdai） |
| `slots.memory` | **冲突** — 只能绑定一个 |
| Prompt 注入 | **冲突** — 同一时机重复注入 |
| 工具调用 | 不冲突（工具名不同） |

## 四、Agent Memory 设计哲学

Agent Memory 不是关于"记住一切"，而是关于"让 Agent 记得该记得的，人类不必重复自己"。

核心原则：
- **分层抽象**：短期/长期/技能生成都用分层范式，上层保留结构，下层保留证据
- **渐进披露**：Agent 上下文只保留轻量结构，细节按需钻取
- **全链追溯**：任何抽象都能无损回溯到原始证据
- **白盒可审计**：中间产物是人类可读的文件（Markdown、Mermaid），不是黑盒向量

## 五、选型建议

| 场景 | 推荐方案 |
|------|----------|
| 简单稳定 | `memory-core + memory-wiki` |
| 长任务优化、token 敏感 | `TencentDB Agent Memory` |
| 都要 | `memory-core` 占 slot，TencentDB 作为补充工具 |

## 五、相关命令

```bash
# 查看插件状态
openclaw plugins list

# 安装 TencentDB
openclaw plugins install @tencentdb-agent-memory/memory-tencentdb

# 查看 slot 绑定
cat ~/.openclaw/openclaw.json | grep -A 3 '"slots"'
```
