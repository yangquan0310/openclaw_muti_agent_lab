# 多Agent管理与单Agent记忆进化体系

> 杨权设计，2026-05-23
> 来源：抖音讨论 + 飞书对话

---

## 一、整体架构

```
用户（唯一沟通入口）
  ↓
总管家Agent（协调层）
  ↓ 协调
业务Agent集群（执行层）
  ↓
各项目仓库（知识层）
  ├── 项目上下文系统
  ├── TODO（任务进度控制）
  └── README + HANDBOOK（协作规范）
```

---

## 二、记忆分布设计

记忆文档**分散**存储在项目和智能体两个层面：

| 存储位置 | 内容 |
|----------|------|
| **项目目录** | 项目级记忆、知识库、上下文 |
| **Agent个人目录** | 自我认知、风格、信念、身份、程序性记忆、技能 |

- 不是集中式存储，而是**就近存储**
- 项目知识在项目目录，Agent认知在Agent个人目录

---

## 三、迭代进化循环

每一次任务迭代，Agent执行以下分析流程：

```
任务完成
  ↓
分析：计划 → 偏差（产出 vs 计划） → 归因
  ↓
四维更新：
  ├── 钩子系统（更准确）
  ├── 提示词系统（更精细）
  ├── 人格系统（更形式化）
  └── 代码系统（更算法化）
  ↓
更新范围：自我认知 · 风格 · 信念 · 身份 · 程序性记忆 · 技能
```

### 偏差定义

```
偏差 = 计划 - 产出（的差距）
```

用于追踪执行质量，驱动自我反思。

---

## 四、任务模板设计

强调四要素，不强调过程：

| 要素 | 说明 |
|------|------|
| **输入** | 给什么 |
| **产出** | 输出什么 |
| **目标** | 要达成什么 |
| **约束** | 边界条件 |
| ~~过程~~ | **不强调**，代理自行细化 |

> 代理负责**自己**将目标→约束→计划，授权执行而非规定步骤。

---

## 五、多Agent协作机制

### 群体上下文窗口
- 飞书群组 = 群体上下文窗口
- 每个项目一个群，防止上下文窗口**串行堆积**
- 群内共享项目上下文，各Agent独立执行

### 层级关系
```
用户 → 总管家（steward） → 业务Agent → 项目仓库
```

---

## 六、项目管理机制

每个项目仓库内：

| 文件 | 作用 |
|------|------|
| **TODO.md** | 任务进度控制 |
| **README.md** | 项目概述 |
| **HANDBOOK.md** | 协作规范 |
| **.agents/** | 任务运行记录、事件归档 |
| **memory/** | 项目级记忆 |

---

## 七、设计意图

| 目标 | 实现方式 |
|------|----------|
| **分布记忆** | 知识就近，避免单点膨胀 |
| **迭代进化** | 每次任务后自我改进 |
| **四维更新** | 系统性提升而非零散打补丁 |
| **代理自主** | 不规定过程，只规定输入输出 |
| **并行化** | 群体上下文避免串行窗口耗尽 |
| **项目隔离** | 独立上下文，独立规范 |

---

## 八、自进化瓶颈讨论

> 来源：抖音评论 @宸风

- 记忆是**基础设施**，不是进化本身
- 真正的瓶颈不在存储策略（艾宾浩斯/时间淘汰），而在**进化什么**
- 核心问题：偏差如何量化、目标如何收敛
- 关键：设计**可量化的自我评测闭环**，而非更大的数据库
