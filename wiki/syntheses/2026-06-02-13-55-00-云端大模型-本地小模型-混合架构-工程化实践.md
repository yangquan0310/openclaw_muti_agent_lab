## 一、核心理念

> **开发期用云端大模型"编剧本"，运行期用本地小模型"照着演"**

- **大B模型**（云端，GPT-4/Qwen-Plus 级别）：离线生成静态的工作流定义、知识库索引、决策规则表
- **小B模型**（本地，Ollama 跑 7B-13B）：严格按开发期产出的"剧本"执行具体任务
- **代理框架**：工作流引擎，负责解析静态定义、调度本地小模型、管理上下文状态
- **Docker**：封装运行期所有组件，实现单机/集群一键部署，无任何外部 API 依赖

---

## 二、两阶段工作流

### 阶段 1：开发期（大B驱动 + 人工介入）

1. **业务理解与知识提取**
   - 输入：业务文档、日志、流程手册
   - 大B输出：
     - 知识库（向量库文件 + 关键词映射表 + 实体关系 JSON）
     - 工作流定义（一个 DAG，每个节点 = "当满足条件 C 时，由本地小模型执行动作 A，输出格式 F"）

2. **生成静态配置**
   - 知识库 → 本地可快速检索的格式（SQLite / FAISS 索引文件）
   - 工作流定义 → 规则引擎可读的 YAML/JSON

3. **验证与固化**
   - 用真实数据回放模拟，确认工作流合理
   - 配置文件 + 知识库制品纳入版本控制，随 Docker 镜像一同构建

### 阶段 2：运行期（纯本地执行，无云端调用）

```
用户请求
   ↓
代理框架（工作流引擎）
   ↓
加载静态工作流定义 + 匹配当前状态
   ↓
DAG 节点匹配 → 调本地小B → 出回复
```

## 三、典型场景：工单系统

```
新工单进来
  ↓
代理框架启动流程
  ↓
本地小模型分类为"退款问题"
  ↓
本地小模型判断情绪为"愤怒"
  ↓
代理框架触发大B模型API
  ↓
"用安抚语气生成退款指引回复"
  ↓
最终回复（2 次预处理本地完成 → 省 2 次云端调用）
```

## 四、组件选型建议

| 组件 | 选型 | 注意事项 |
|------|------|---------|
| 小B模型 | Ollama 跑 7B~13B | 需函数调用或指令跟随能力 |
| 代理框架 | LangChain / Semantic Kernel / 自研网关 | 支持混合模型路由、状态持久化、成本计量 |
| 知识库 | SQLite / FAISS | 本地可快速检索 |
| 部署 | `ollama/ollama` 官方 Docker 镜像 | 挂载卷缓存小模型文件 + 环境变量注入大模型 API_key |

---

## 五、核心优势

1. **成本最优**：高频预处理本地化 → 大B 只在必要时调用 → 显著节省 token
2. **数据安全**：敏感数据不出本地（情绪判断、意图分类都在本地）
3. **低延迟**：本地小B 响应快（不绕云端）
4. **可移植**：Docker 化后单机/集群一键部署，无云端依赖即可运行

## 六、与 OpenClaw 现状的对比

| 维度 | DeepSeek 描述 | OpenClaw 现状 | 评估 |
|------|---------------|--------------|------|
| 大小模型分工 | 开发期大B / 运行期小B | 全程大模型（MiniMax-M3 等）| OpenClaw 缺本地小B 层 |
| 工作流定义 | DAG（YAML/JSON）| 部分用 cron + 简单 if-then | 缺结构化工作流引擎 |
| 代理框架 | 混合模型路由 + 状态管理 | Gateway RPC + 多 agent 协作 | 部分重叠，OpenClaw 没有本地执行层 |
| 部署 | Docker + Ollama 镜像 | 主要是 SaaS 部署 | OpenClaw 缺本地化部署 |

**潜在启发**：
- OpenClaw 可以考虑增加"本地小模型预处理层"，把高频、低成本任务本地化
- 子代理的 if-then 规则可以演化为"工作流定义"，与 Workboard 看板结合
- Docker 化部署对"私有化部署"场景（企业内网/离线环境）有参考价值
