# If-Then 规则修改标准

> 适用对象：各代理 MEMORY.md 中的「程序性记忆 / 条件-行动规则」
> 修改原则：精简、归一、可执行

---

## 一、规则准入标准（什么能进 If-Then）

If-Then 规则只保留**三句话能说清、且必须靠记忆提醒才不误触**的操作性指令。

| 能进 If-Then ✅ | 不能进 If-Then ❌ |
|---------------|------------------|
| 涉及**跨工具组合**的固定流程 | 单个工具的基础用法 |
| 容易**误操作**（覆盖、泄露、越权）的安全动作 | 通用常识 |
| 与**特定外部系统**的交互约定 | 已写入 AGENTS.md 的全局规范 |
| 需要**判断条件**才能触发的分支流程 | 无条件的绝对指令 |

---

## 二、规则删除标准（什么该删除）

满足任一条件即删除：

| 删除条件 | 示例 |
|---------|------|
| **已整合到 AGENTS.md** | 飞书消息发送方式、子代理使用规则 |
| **项目已完成且无复用价值** | "数字化存储项目完成 → git 提交" |
| **纯知识/数据** | open_id 列表、工具参数说明 |
| **过于笼统无法执行** | "用户说完成 → 更新状态" |
| **与当前工具链脱节** | 引用了已删除的工具/流程 |

---

## 三、规则合并标准（什么该合并）

满足**全部**条件即合并为一条：

1. **同一场景**：触发条件属于同一工作流
2. **同一动作**：执行的是同一类操作
3. **无冲突**：合并后不会导致条件判断矛盾

---

## 四、规则迁移标准（什么该移到别处）

| 当前位置 | 迁移目标 | 内容类型 |
|---------|---------|---------|
| If-Then | **陈述性记忆 / Wiki** | open_id、路径常量、工具参数 |
| If-Then | **AGENTS.md**（全局规范） | 所有代理都必须遵守的通用规则 |
| If-Then | **SKILL.md**（技能文档） | 工具组合的标准操作流程 |

---

## 五、规则格式标准（怎么写）

| 要素 | 要求 |
|-----|------|
| **条件** | 用引号标注用户原话，或明确工具名 + 状态 |
| **行动** | 动词开头，主语省略，不加修饰语 |
| **粒度** | 一行只描述一个动作，多动作用分号 |
| **时效** | 如规则有过期时间，用 `TODO(日期)` 标注 |

**好示例**：
> `feishu_create_doc` 创建后 → 提醒用户文档归属为应用，需手动转移所有权

**坏示例**：
> 用户使用飞书相关功能时 → 注意相关权限问题并做好相应处理
