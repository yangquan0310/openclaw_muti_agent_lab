## 二、逐项审计

### A. 中文表达质量（25 / 30）

#### 优点

1. **触发场景用动词开头 + 编号**，LLM 易解析：
   ```
   1. 检索论文（Semantic Scholar / CNKI / Google Scholar）
   2. 拉 PDF 到 WebDAV（坚果云）
   ```
   句子结构稳定，便于语义匹配。

2. **核心原则用"加粗短语 + 解释"** 格式：
   ```
   **Git 版本控制**：使用 Git 管理版本，不需要额外归档
   ```
   重点突出，解释充分。

3. **术语准确**：wiki ↔ Zotero ↔ WebDAV "三联动" 全篇一致，未混淆"三联动 / 三方 / 三层"。

#### 问题

1. **个别口语化表述**（如出现在版本历史）：
   - "工具不攥写 narrative" → "攥写"是动词口语化表达，与上下文偏正式的"撰写 / 生成 / 写作"不一致
   - "metadata 唯一权威" → "唯一权威"偏口语，改为"唯一权威来源"或"权威来源"更书面

2. **"兑底链"用字错误**（v6.0.6 行）：
   - 原文：`OPENCLAW_AGENT_NAME → ... → "unknown"` 兑底链
   - 应为：**"兜底链"**（"兑"是错字）

3. **括号注释略冗余**（触发场景 #4）：
   - "本地 PDF 反向上传到 Zotero + WebDAV + wiki source（v6.0.3+ upload）"
   - 末尾的"(v6.0.3+ upload)"和前文"反向上传"语义重复——已知要上传，版本号标注可保留但"upload"一词不必要

4. **快速调用表格标题"7 模块核心参数"**——下面列出 6 行（search/download/summarize/synthesize/manage/maintain），**少了 upload**：
   - 表格遗漏 v6.0.3+ 上传模块
   - 触发场景里写了 11 个场景，"7 模块核心参数"只覆盖 6 个——模块清单不一致

#### 改进建议

- "攥写" → "撰写"（3 处全部替换）
- "兑底" → "兜底"
- "7 模块核心参数"表格补一行 `upload`（与"快速调用"代码块一致）
- 触发场景 #4 删除末尾"(v6.0.3+ upload)"，或保留版本号去掉英文

### C. 结构清晰度（17 / 20）

#### 优点

1. **YAML frontmatter** → 标题 → 触发场景 → 核心原则 → 边界 → 快速调用 → 指南导航 → 模板 → 数据流 → 目录结构 → 版本历史——**章节顺序符合"识别信号 → 能力 → 用法 → 索引"逻辑**，对 LLM 解析友好。

2. **H2 标题用动词 / 名词短语**，无模糊标题（如"概览" / "其他"）。

3. **代码块 + 表格 + 列表三种结构穿插使用**——视觉层次合理。

#### 问题

1. **指南导航表格编号跳跃**（关键问题）：
   ```
   | 14 | PRISMA 系统综述 SOP（v5.21.0 新增）| ... |
   | 16 | APA 7 引用核验（v5.21.0 新增）| ... |
   ```
   - **#15 缺失**——目录树里第 15 项应是 narrative/meta/observational/experimental 4 个文体指南之一，但表格直接跳过
   - 实际是因为表格上方缺了 4 行"4 文体"——结构断裂
   - 建议：要么补 4 行（#15-18 文体指南）使 18 行连续，要么改用 `<details>` 折叠

2. **"目录结构"段前有 1 行空白但和"数据流"段没有明确视觉分隔**——两个代码块紧挨着，读者容易混淆边界。

3. **"快速调用"段末尾用 `---` 分隔线**，但 SKILL.md 全文只在版本历史前出现一次 `---`——分隔风格不统一。

#### 改进建议

- 指南导航表格 #15 补上 narrative-review / meta-analysis / observational-study / experimental-study 4 个文体指南行
- "数据流" / "目录结构"两段之间加 `## 目录结构（v5.20.0+ wiki 后端）` H2 标题后留 1 空行
- 全文 `---` 分隔线规范为：每个大章节末尾才用

### D. 一致性（14 / 20）

#### 关键不一致点

1. **模块数不一致**（README vs SKILL.md）：
   - README 七大核心功能：检索 / 下载 / manage / summarize / synthesize / upload / 排版 → **7 个**
   - SKILL.md "快速调用"代码块：`search / download / upload / summarize / synthesize / manage / maintain` → **7 个**（maintain 不在 README 的"七大核心功能"）
   - SKILL.md "7 模块核心参数"表格：只有 6 行（**缺 upload**）
   - SKILL.md "目录结构"：`search/ / download/ / upload/ / summarize/ / synthesize/ / manage/ / maintain/` → **7 个目录**
   - **结论**：README 的"七大核心功能"与 SKILL.md 的模块清单在 maintain / 排版 之间有出入——SKILL.md 是技术真实（maintain 是 CLI 模块），README 是用户视角（排版是手写 Quarto 命令）

2. **触发场景数量 = 11，但"指南导航"只有 18 条**——其中 4 文体指南（narrative / meta / observational / experimental）在"指南导航"是单独条目，但在"触发场景"**没有对应一行**——读者预期能从触发场景 → 找文体指南的入口断链。

3. **版本号标注不一致**：
   - "**v6.0.6**"在版本历史里是"代码 polish"
   - 但"快速调用"段标注 `v5.20.0+` 实际命令
   - "触发场景"段标注 `v6.0.3+ upload`
   - "核心原则"段标注 `v5.20.0 起`
   - "边界条件"无版本号
   - **标注逻辑不统一**——哪些是"何时引入" / 哪些是"当前版本" / 哪些是"稳定" 没说清

4. **术语不统一**：
   - "wiki 后端" vs "wiki↔Zotero↔WebDAV 三联动"——两个说法都出现，未明确"三联动 = wiki 后端 + Zotero + WebDAV"
   - "工具不攥写 narrative" vs "工具不替代 agent"——同一原则两种说法

#### 改进建议

- 在 SKILL.md 顶部加 1 段"模块对照表"（7 CLI 模块 vs README 7 功能 vs 真实目录），消除歧义
- 触发场景补一行"4 文体指南"（narrative / meta / observational / experimental）
- 版本号标注规范化：`(vX.Y.Z+ 表示 X.Y.Z 及以上版本可用)`
- 选定一个术语："工具不替代 agent"（优于"工具不攥写 narrative"）

### E. 用户友好度（8 / 10）

#### 优点

1. **"快速调用"段是入口**——LLM / 老人都能直接抄命令。
2. **"指南导航"表格按编号列出 references**，索引清晰。

#### 问题

1. **新人首次阅读不知道从哪开始**：
   - 没有"快速开始"——直接进"触发场景"，但触发场景需要先知道"我是 LLM"还是"我是人"
   - 建议：在标题后加 1 段"使用说明"——3 行说明这是给 LLM 看的入口 + 人应看 README + 改文档从这里开始

2. **缺少"如何修改本文档"指南**——SKILL.md 是 skill 的入口，谁改、什么时候改、改完怎么验证，没有文档说明。

3. **"数据流总览"5 阶段写得简练，但每阶段末尾"jina-ai/Tavily 补充检索 → agent 拿到笔记后自己攥写 narrative（工具不攥写）"**——括号内注对新人有帮助，但 LLM 视角不需要。

#### 改进建议

- 标题"## research-assistant（研究助手）"后加 1 行"LLM 入口：识别触发场景 → 调 7 模块 CLI → 必要时查 references"
- 加 1 段"维护说明"：本文档变更需走 v6.0.4+ 12 项审计清单 + 同步更新 README
- 数据流括号注释改为独立 1 行（`注：工具只提供数据，攥写由 agent 完成`）
