## 参与角色与职责

| 角色 | Agent ID | 职责范围 | 核心能力 |
|------|----------|----------|----------|
| **心理专家** | psychologist | 文献综述 + 讨论初稿 | 心理学专业知识、文献检索、APA格式 |
| **写作专家** | writer | 整合全文 + 变量修正 + 修改报告 | 学术写作、格式规范、跨章节一致性 |
| **审稿助手** | reviewer | 全文审核 + 审稿意见 | 质量检查、数据审核、格式审查 |
| **大管家** | steward | 文件归档 + 版本管理 + 云文档上传 | 文件管理、版本控制、交付管理 |

## 协作流程

### 阶段1：任务分配（用户协调）
1. 用户将论文修改任务分配给 **psychologist**（擅长文献综述与讨论）
2. psychologist 完成文献综述 A1/A2/A3 和讨论 B1/B2
3. psychologist 输出新增参考文献（32篇，APA 7th）
4. psychologist 在 **TODO.md** 标记任务完成，向用户汇报

### 阶段2：举手请求协作
- psychologist 发现需要 **writer** 整合全文
- 在 TODO.md「待分配」写入子任务：
  > 「我擅长文献综述，但全文整合和变量清理需要写作专家。建议分配给 writer。」
- 用户收到后，将子任务分配给 writer

### 阶段3：writer 执行（含多轮修正）
- **Fix-R1**：结果部分变量混淆清理
- **Fix-R2**：跨章节变量混淆清理
- **Fix-R3**：文献综述与讨论整合（含网络欺凌残留清理）
- **Fix-R5**：审稿意见修正（6项修正）
- 每轮修正后更新 TODO.md，标记进度

### 阶段4：reviewer 审核
- reviewer 读取 writer 终稿
- 执行 8 项审核：
  1. 变量一致性 ✅
  2. 方向性审核 ⚠️（发现β值舍入误差）
  3. 假设-数据-结论一致性 ✅
  4. 摘要一致性 ✅
  5. 文献引用审核 🔴（9篇未引用）
  6. 表格数据审核 🔴（表4.4β值不一致）
  7. 逻辑连贯性审核 🔴（结论提及"学历"变量）
  8. 格式规范审核 🟡（中英文括号混用）
- 输出 **审稿意见.md**，发现🔴问题 → 返回 writer 修正

### 阶段5：steward 归档
- 接收 writer 交付物（论文_R1.md、修改报告.md、审稿意见.md）
- 文档归档：
  - 终稿 → `manuscripts/`
  - 修改报告 → `docs/`
  - 审稿意见 → `docs/`
- Git 提交：`git commit -m "🔖 commit: ch01 v2: 论文修改完成"`
- 更新 README.md 版本记录（v1 → v2）
- 待确认：上传云文档

## 关键协作机制

### 1. TODO.md 进度看板
- 5个状态列：待办 / 进行中 / 待分配 / 待确认 / 已完成
- 任务格式：`- [ ] 任务名 — @agent-id — HH:MM开始 — 来源：用户分配`
- 流转规则：完成者移到「待确认」→ 用户 [APPROVED] → 移到「已完成」→ 归档

### 2. 文件系统协作
- **manuscripts/**：Agent 工作草稿（writer 产出论文_R1.md）
- **docs/**：定稿（用户确认后归档）
- **knowledge/**：项目知识（心理学家文献综述产出）

### 3. 举手请求协议
- Agent 发现需其他能力时，写入 TODO.md「待分配」
- 汇报用户：「我擅长X，但需要Y。建议分配给擅长Y的Agent。」
- 用户协调后分配新 Agent

### 4. 审核流转机制
- reviewer 发现 🔴 问题 → 返回原 Agent 修正
- 修正后重新审核 → 无 🔴 → 交付 steward 归档

## 经验总结

### 成功要素
1. **明确的角色分工**：每个 Agent 有清晰的能力边界
2. **TODO.md 驱动**：所有 Agent 通过同一进度看板了解全局状态
3. **审核闭环**：reviewer 的 8 项审核清单确保质量
4. **举手不阻塞**：psychologist 发现需 writer 时，先完成自己部分再举手

### 可改进点
1. **缺少 .openclaw/ 元数据层**：无 events/、tasks/、locks/ 结构化记录
2. **缺少自动化流转**：审核发现问题后需手动返回，无状态机自动流转
3. **版本管理人工化**：steward 手动移动文件，缺少自动化归档
4. **无冲突检测**：若多 Agent 同时编辑同一文件，无锁机制

### 对 v4.0.0 的启示
- 该实践验证了「文件系统协作 + TODO.md 进度看板」模式的可行性
- v4.0.0 的「四文件契约」「文件移动协议」「状态机」可直接复用该实践的经验
- 该实践可作为 v4.0.0 的「首个落地案例」写入开发计划
