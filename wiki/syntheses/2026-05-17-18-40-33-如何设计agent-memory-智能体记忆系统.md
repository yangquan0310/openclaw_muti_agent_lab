# Agent Memory（智能体记忆系统）

> Agent Memory 的设计哲学、技术路线与选型指南。

---

## 一、什么是 Agent Memory

Agent Memory 是**为大语言模型（LLM）驱动的智能体提供持久化记忆能力的系统**。它解决的核心问题是：

> LLM 的上下文窗口有限（通常 4K-128K tokens），无法在一次会话中承载完整的工作历史、个人偏好和领域知识。

Agent Memory 让智能体能够：
- **记住** 之前的对话、决策和结果
- **回忆** 相关历史来辅助当前决策
- **学习** 从经验中提炼规则，持续进化

---

## 二、设计哲学

### 哲学 1：人脑仿生（Neuro-mimetic）

借鉴人类记忆的认知科学分层：

| 人脑记忆类型 | Agent Memory 对应层 | 特征 |
|-------------|---------------------|------|
| **感觉记忆** | 会话上下文（Context） | 极短，实时衰减 |
| **工作记忆** | Working Memory / MEMORY.md | 当前任务相关，主动维护 |
| **短期记忆** | Short-term / Light Dreams | 近期事件，快速联想 |
| **长期记忆** | Long-term / Deep + REM Dreams | 模式提取，慢速巩固 |
| **程序性记忆** | Procedural Memory（If-Then 规则） | 技能、习惯、自动化决策 |
| **语义记忆** | Wiki / 知识库 | 事实性知识，去情境化 |

### 哲学 2：分层解耦（Layered Decoupling）

每层记忆独立设计，不互相依赖：
- **L1 上下文层**：由 LLM 推理框架管理（OpenClaw、LangChain 等）
- **L2 工作层**：由 Agent 个人文件管理（MEMORY.md）
- **L3 知识层**：由全局知识库管理（Wiki、向量数据库）
- **L4 外部层**：由专用系统管理（业务数据库、向量检索服务）

### 哲学 3：可插拔架构（Pluggable Architecture）

不绑定单一存储后端，支持多种实现：
- **文件型**：Markdown + 本地索引（OpenClaw 默认）
- **向量型**：Chroma / Milvus / Pinecone（语义检索）
- **图型**：Neo4j / TigerGraph（关系推理）
- **混合型**：文件 + 向量 + 图的组合

### 哲学 4：Agent 自治（Agent Autonomy）

记忆不是被动的"数据仓库"，而是 Agent 主动管理的资源：
- Agent 决定**何时写入**记忆
- Agent 决定**何时检索**记忆
- Agent 决定**何时遗忘**（清理过期/冲突信息）

## 三、技术路线对比

### 路线 A：文件-语义混合（OpenClaw 路线）

| 维度 | 说明 |
|------|------|
| **存储** | Markdown 文件 + 本地语义索引 |
| **检索** | 语义搜索（`memory_search`）+ 精确读取（`memory_get`） |
| **更新** | 自动（会话结束索引化）+ 手动（Agent 编辑 MEMORY.md） |
| **优势** | 人类可读、可版本控制（Git）、零外部依赖 |
| **劣势** | 大规模数据（>10万条）性能下降 |
| **适用** | 个人 Agent、小型团队、可解释性要求高的场景 |

**核心创新：梦境机制（Dreaming）**
- Light Dreams：会话语料快速索引
- Deep Dreams：模式提取、冲突检测
- REM Dreams：跨会话整合、人格/规则更新

### 路线 B：向量数据库（RAG 路线）

| 维度 | 说明 |
|------|------|
| **存储** | 向量数据库（Chroma / Milvus / Weaviate） |
| **检索** | Embedding 相似度搜索 |
| **更新** | 显式 API 调用（插入/更新/删除） |
| **优势** | 海量数据、毫秒级检索、数学/科学文档友好 |
| **劣势** | 需要外部服务、非人类可读、调试困难 |
| **适用** | 大规模知识库、企业级应用、多模态数据 |

### 路线 C：结构化数据库（TencentDB-Agent-Memory 路线）

| 维度 | 说明 |
|------|------|
| **存储** | 关系型/NoSQL 数据库（如 TencentDB for MySQL） |
| **检索** | SQL 查询 + 向量检索混合 |
| **更新** | 事务化写入，支持 ACID |
| **优势** | 强一致性、事务支持、与现有业务系统集成 |
| **劣势** |  Schema 设计复杂、灵活性低 |
| **适用** | 企业级 Agent、金融/医疗等高一致性场景 |

### 路线 D：分层缓存（MemGPT 路线）

| 维度 | 说明 |
|------|------|
| **存储** | 内存缓存 + 磁盘溢出 + 外部存储 |
| **检索** | 自管理的分页/换页机制 |
| **更新** | Agent 自主决定换入换出 |
| **优势** | 对 LLM 透明、模拟操作系统虚拟内存 |
| **劣势** | 实现复杂、对开发者不透明 |
| **适用** | 超长对话、聊天机器人、客服场景 |

## 四、路线选型指南

| 场景 | 推荐路线 | 理由 |
|------|----------|------|
| 个人助理 / 研究助手 | **A（文件-语义）** | 可解释、可版本控制、零运维 |
| 企业知识库问答 | **B（向量数据库）** | 海量文档、高性能检索 |
| 金融/医疗 Agent | **C（结构化数据库）** | 事务一致性、审计追踪 |
| 超长对话机器人 | **D（MemGPT）** | 透明分页、上下文管理 |
| **混合场景** | **A + B + C** | 不同数据类型用不同后端 |

## 五、多系统共存：会"打架"吗？

**不会。** 正确的架构是**互补而非替代**：

```
┌─────────────────────────────────────┐
│           Agent 推理层               │
│  （LLM / OpenClaw / LangGraph）      │
└──────────────┬──────────────────────┘
               │
    ┌──────────┼──────────┐
    │          │          │
    ▼          ▼          ▼
┌───────┐ ┌───────┐ ┌───────────┐
│ L1    │ │ L2    │ │ L3        │
│上下文  │ │工作记忆│ │ 外部记忆   │
│(默认)  │ │(MEMORY│ │(TencentDB │
│       │ │ .md)  │ │ / 向量库)  │
└───────┘ └───────┘ └───────────┘
```

**共存原则：**
1. **命名空间隔离**：每个记忆源有独立 ID，Agent 通过工具名区分
2. **用途分离**：
   - L1+L2：个人工作流、任务状态、If-Then 规则
   - L3：领域知识、历史数据、大规模语料
3. **Agent 自主路由**：通过 If-Then 规则决定查询哪个记忆源

## 六、OpenClaw 的具体实现

OpenClaw 采用 **路线 A（文件-语义混合）** 作为默认架构：

| 层级 | 路径 | 机制 |
|------|------|------|
| L1 上下文 | 会话消息链 | 自动携带最近 N 条 |
| L2 工作记忆 | `MEMORY.md` | 会话开始时注入 |
| L2.5 浅层梦境 | `memory/dreaming/light/` | 会话结束自动索引 |
| L3 深层梦境 | `memory/dreaming/deep/` | 夜间批量处理 |
| L3.5 REM 梦境 | `memory/dreaming/rem/` | 跨会话整合 |
| L4 全局知识 | `wiki/` | 语义搜索 + 合成写入 |

**对接其他路线的方式：**
- 通过 **Skill** 封装外部系统 API（如 TencentDB 查询）
- 通过 **MCP 服务器** 暴露为标准化工具
- Agent 在 `MEMORY.md` 中写入规则，决定何时调用外部记忆

---

## 七、最佳实践

1. **默认用官方记忆**：个人任务、规则放在 `MEMORY.md`
2. **Wiki 存公共知识**：跨 Agent 共享的事实写入 Wiki
3. **外部系统按需接入**：大规模/专业数据用向量库/数据库
4. **避免重复存储**：同一事实只维护一个"权威源"
5. **定期整理**：使用 `wiki-maintainer` 等工具清理冲突和过期信息

### 8.3 选型速查表

| 场景 | 首选方案 | 理由 |
|------|----------|------|
