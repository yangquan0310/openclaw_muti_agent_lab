## 主题一：记忆评估方法论

### 文章 1：MemDelta
- **标题**：MemDelta: Controlled Baselines and Hidden Confounds in Agent Memory Evaluation
- **作者**：Kuan Wang
- **时间**：2026-06-30（Published Time: 2026-06-30 01:34 GMT）
- **主要内容**：针对 Agent 记忆系统评估中的"混淆变量"问题，提出控制变量评估协议 MemDelta，基于 LongMemEval-S（500 题、50+ 会话、3 模型家族）。关键发现：(1) 逐字 RAG 与全上下文 GPT-4o-mini 准确率相当（47.2% vs 49.8%, p=0.34），但跨模型排名反转——Gemini 全上下文增益 +14pp，Sonnet RAG 增益 +31pp（部分因其拒绝 63% 全上下文查询）；(2) 仅替换嵌入模型即可造成 +6.2pp 偏差（p=0.004）；(3) Mem0 优于 MiniLM-RAG +11pp 但输于 cloud-RAG 1.2pp；(4) 2/6 问题类型上 Mem0 与 cloud-RAG 持平（72.7% vs 73.9%），但成本 50 倍。**对评估方法论的强提醒**：建议锁定嵌入模型、按模型家族分层、上报写路径成本。

### 文章 2：Always-On Agents
- **标题**：Always-On Agents: A Survey of Persistent Memory, State, and Governance in LLM Agents
- **作者**：Tianyu Ding, Aditya Nannapaneni, Bingfan Liu, Ling Zhang
- **时间**：2026-06-30（Published Time: 2026-06-30 01:58 GMT）
- **主要内容**：将"Always-On Agent"建模为持久状态系统，除可检索记忆外还包含任务账本、权限、凭证、承诺、来源与审计记录、共享状态、触发条件与外部提交效应。通过 6 个诊断轴（authority、scope、mutability、provenance、recoverability、actionability）与生命周期（写入-验证-组织-检索-行动-更新-遗忘-审计-回滚）对 435 篇文献编码分析。提出 Always-On Evaluation Protocol (AOEP-v0)，按状态变更与恢复义务评分而非仅答案质量，连接数据库/分布式系统/形式化方法/能力安全/机器遗忘。

## 主题二：程序性记忆范式转移

### 文章 3：Neural Procedural Memory
- **标题**：Neural Procedural Memory: Empowering LLM Agents with Implicit Activation Steering
- **作者**：Chengfeng Zhao, Yuqiao Tan, Shizhu He, Yequan Wang, Jun Zhao, Kang Liu
- **时间**：2026-06-30（Published Time: 2026-06-30 01:28 GMT）
- **主要内容**：针对 RAG 注入显式文本指令带来的"文本-动作脱节"问题，提出无需训练的 Neural Procedural Memory (NPM) 框架——通过历史对比经验蒸馏出激活空间中的 steering vectors，直接激活任务相关神经机制。在 4 个 Agent 基准上与显式文本指令基线持平或更优；隐式引导与显式工作流结合互补性显著。表征分析显示 steering vectors 在激活空间形成有组织的结构，编码一致的任务逻辑。**意义**：标志着 Agent 记忆从"显式文本"向"隐式神经激活"范式转移。

## 主题三：多 Agent 记忆拓扑

### 文章 4：HyphaeDB
- **标题**：HyphaeDB: A Living Knowledge Topology for Agent-First Memory
- **作者**：Krishna Halaharvi
- **时间**：2026-06-30（Published Time: 2026-06-30 00:26 GMT）
- **主要内容**：重新诠释 HNSW 图拓扑——从"搜索优化数据结构"升格为"多 Agent 通信媒介"。在 HyphaeDB 中，Agent 是向量空间中的持久节点，知识通过 gossip 协议沿图邻居结构传播并伴随能量衰减；涌现出矛盾检测、模式结晶、共识形成等行为。基于 PostgreSQL + pgvector 实现，落地"Swarm-Driven Development"多 Agent 软件工程方法。理论根基为小世界网络、流行病广播协议、群体智能。**意义**：首个将可导航小世界拓扑与 gossip 知识传播结合用于多 Agent 协调的系统。
