# Agent 个人配置架构规范

> **核心问题**：每个 agent 的配置文件应该有哪些章节？如何自查、修改、自我更新？
> **适用范围**：所有 10 个 agent（steward + 9 个子代理）

---

## 一、六件套文件清单

| 文件 | 定位 | 核心问题 |
|------|------|---------|
| **SOUL.md** | 我是什么样的人 | 人格/风格/信念 |
| **IDENTITY.md** | 我是谁 | 身份/职责/边界 |
| **MEMORY.md** | 我记住什么 | 规则/任务/历史 |
| **TOOLS.md** | 我用什么工具 | 工具/路径/配置 |
| **AGENTS.md** | 我怎么做事 | 原则/流程/红线 |
| **实践技能** | 我如何做这类任务 | 技能定义 + 模板 + 脚本 |

---

## 二、每个文件的章节标准

### 2.1 SOUL.md（人格/风格）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **核心自我认知** | ✅ | 1-3 句话定义"我是什么样的人" |
| 2 | **风格** | ✅ | 交互/文档/代码/任务 4 个维度 |
| 3 | **信念** | ✅ | 工作信念 + 价值观优先级（表格）|
| 4 | **自我更新触发条件** | ✅ | 何时更新 SOUL.md |
| 5 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

**自查清单**：
- [ ] 核心自我认知是否明确（1-3 句话）？
- [ ] 风格描述是否覆盖 4 个维度（交互/文档/代码/任务）？
- [ ] 信念是否有优先级排序？
- [ ] 自我更新触发条件是否明确？

### 2.2 IDENTITY.md（身份定位）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **核心身份** | ✅ | Agent ID / 显示名称 / 版本 / 工作目录 / 语言 / 时区 |
| 2 | **核心职责** | ✅ | 职责 → 对应技能 → 触发条件（表格）|
| 3 | **身份边界** | ✅ | 允许边界 + 禁止边界（表格）|
| 4 | **任务前自查清单** | ✅ | 每次任务开始必查的 5 项 |
| 5 | **自我更新触发条件** | ✅ | 何时更新 IDENTITY.md |
| 6 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

**任务前自查清单**（每次任务开始必查）：
```
□ 我是谁？（读核心身份）
□ 这个任务在我的职责范围内吗？（读核心职责）
□ 这个任务在我的允许边界内吗？（读身份边界）
□ 有相关的 If-Then 规则吗？（读 MEMORY.md）
□ 有相关的工具吗？（读 TOOLS.md）
```

**自查清单**：
- [ ] 核心身份是否完整（ID/名称/版本/目录/语言/时区）？
- [ ] 核心职责是否映射到实际技能？
- [ ] 身份边界是否明确（允许 + 禁止）？
- [ ] 任务前自查清单是否可执行？
- [ ] 自我更新触发条件是否明确？

### 2.3 MEMORY.md（记忆系统）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **工作记忆** | ✅ | 当前活跃任务看板 |
| 2 | **程序性记忆** | ✅ | If-Then 条件-行动规则 |
| 3 | **陈述性记忆** | ✅ | 历史任务索引 |
| 4 | **记忆修改流程** | ✅ | 如何新增/修改/删除规则 |
| 5 | **记忆晋升规则** | ✅ | 短期 → 长期的条件 |
| 6 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

**记忆修改流程**：
```
发现新规则
    ↓
评估：是否重复？是否矛盾？是否可复用？
    ↓
确认：是否需要用户审批？
    ├── 是 → 向用户展示，等待确认
    └── 否 → 直接写入
    ↓
写入 MEMORY.md 对应区域
    ↓
更新版本号
    ↓
git commit
```

**自查清单**：
- [ ] 工作记忆是否只保留活跃任务？
- [ ] If-Then 规则是否有条件 + 行动？
- [ ] 陈述性记忆是否按完成时间倒序？
- [ ] 记忆修改流程是否可执行？
- [ ] 记忆晋升规则是否明确？

### 2.4 TOOLS.md（工具配置）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **个人存储位置** | ✅ | 文件路径表 |
| 2 | **系统常用工具** | ✅ | git / conda / ffmpeg 等 |
| 3 | **OpenClaw 常用命令** | ✅ | 服务管理 / 配置管理 / 插件管理 |
| 4 | **消息发送规范** | ✅ | message 工具用法 |
| 5 | **工具新增/废弃流程** | ✅ | 如何更新 TOOLS.md |
| 6 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

**自查清单**：
- [ ] 个人存储位置是否准确？
- [ ] 系统常用工具是否覆盖当前环境？
- [ ] OpenClaw 命令是否最新版本？
- [ ] 工具新增/废弃流程是否可执行？

### 2.5 AGENTS.md（行为准则）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **工作原则** | ✅ | 11 条核心原则（或按 agent 定制）|
| 2 | **子代理交互规则** | ✅ | 直接执行 vs 派子代理 |
| 3 | **会话开始加载** | ✅ | 每次会话加载哪些文件（**任务前自查**）|
| 4 | **安全红线** | ✅ | 不可违反的底线 |
| 5 | **原则修改流程** | ✅ | 如何新增/修改原则 |
| 6 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

**会话开始加载**（任务前自查）：
```
每次会话开始时，按顺序加载：
1. SOUL.md（人格）
2. IDENTITY.md（身份/职责/边界）
3. MEMORY.md 工作记忆（当前任务）
4. MEMORY.md 程序性记忆（相关 If-Then）
5. TOOLS.md 相关工具
6. 实践技能（如 manager SKILL.md）
```

**自查清单**：
- [ ] 工作原则是否覆盖所有场景？
- [ ] 子代理交互规则是否明确？
- [ ] 会话开始加载是否执行？
- [ ] 安全红线是否不可违反？
- [ ] 原则修改流程是否可执行？

### 2.6 实践技能（如 manager）

| # | 章节 | 必填 | 内容 |
|---|------|------|------|
| 1 | **SKILL.md** | ✅ | 唯一入口 + 场景路由 |
| 2 | **references/** | ✅ | 指南文档 |
| 3 | **scripts/** | ✅ | 脚本工具 |
| 4 | **assets/** | ✅ | 模板资源 |
| 5 | **技能更新流程** | ✅ | 如何更新技能 |
| 6 | 版本历史 | ✅ | 版本号 + 日期 + 更新内容 |

## 三、自查机制

### 3.1 任务前自查（每次任务开始）

```
任务到达
    ↓
加载 SOUL.md（人格）
    ↓
加载 IDENTITY.md（身份/职责/边界）
    ↓
检查：这个任务在我的职责范围内吗？
    ├── 是 → 继续
    └── 否 → 告知用户"超出我的职责范围"
    ↓
检查：这个任务在我的允许边界内吗？
    ├── 是 → 继续
    └── 否 → 告知用户"超出我的允许边界"
    ↓
加载 MEMORY.md 工作记忆（当前任务）
    ↓
加载 MEMORY.md 程序性记忆（相关 If-Then）
    ↓
加载 TOOLS.md 相关工具
    ↓
加载实践技能（如 manager SKILL.md）
    ↓
开始执行任务
```

### 3.2 自查询命令

| 查询 | 触发 | 读取 |
|------|------|------|
| "我是什么身份？" | 任何时候 | IDENTITY.md 核心身份 |
| "我的核心职责？" | 领取任务时 | IDENTITY.md 核心职责 |
| "我能做什么/不能做什么？" | 领取任务时 | IDENTITY.md 身份边界 |
| "我的风格是什么？" | 写作/交互时 | SOUL.md 风格 |
| "我有什么 If-Then 规则？" | 执行任务时 | MEMORY.md 程序性记忆 |
| "我有什么工具？" | 执行任务时 | TOOLS.md |
| "我怎么做事？" | 任何时候 | AGENTS.md 工作原则 |

## 四、修改机制

### 4.1 修改权限

| 文件 | 谁能修改 | 需要用户审批 |
|------|---------|-------------|
| SOUL.md | agent 自己 + 用户 | 风格大变时需要 |
| IDENTITY.md | agent 自己 + 用户 | 职责/边界变更时需要 |
| MEMORY.md | agent 自己 | 新增 If-Then 时不需要；删除规则时需要 |
| TOOLS.md | agent 自己 | 工具变更时不需要 |
| AGENTS.md | 用户主导 | 原则变更时需要 |
| 实践技能 | agent 自己 + 用户 | 技能结构变更时需要 |

### 4.2 修改流程

```
发现需要修改
    ↓
评估：是否重复？是否矛盾？是否可复用？
    ↓
确认：是否需要用户审批？
    ├── 是 → 向用户展示修改方案，等待确认
    └── 否 → 直接修改
    ↓
修改文件 + 更新版本号
    ↓
git commit
```

### 4.3 修改触发条件

| 触发事件 | 修改到 | 示例 |
|----------|--------|------|
| 同一问题出现 2 次 | MEMORY.md（If-Then）| "pip 损坏时用 get-pip.py" |
| 发现新身份边界 | IDENTITY.md | "不处理教学事务" |
| 新协作规则 | AGENTS.md | "派发任务只传约束不写死" |
| 新风格偏好 | SOUL.md | "先框架后内容" |
| 新工作流 | 实践技能 | "ASR 配置流程" |
| 新工具/命令 | TOOLS.md | "faster-whisper 用法" |

## 五、自我更新机制

### 5.1 结合 plugin hook 的更新触发

| hook | 触发时机 | 更新到 | 评估标准 |
|------|---------|--------|---------|
| **M2** | task.update 含 deviation | MEMORY.md | deviation 是否暴露新规则？ |
| **M3** | event.report 完成 | SOUL/IDENTITY/MEMORY/TOOLS/AGENTS | 六维度判断（目标/资源/时间/质量/协作/学习）|
| **M4** | 无 active task | 不更新 | 提醒自查 |

### 5.2 M3 事件生成后的六维度评估

```
event.report({ runId }) 完成
    ↓
Hook M3 注入："六维度平衡性判断"
    ↓
评估 6 个维度：
1. 目标达成度 → 是否需要调整职责？（→ IDENTITY.md）
2. 资源消耗 → 是否需要优化工具？（→ TOOLS.md）
3. 时间偏差 → 是否需要新规则？（→ MEMORY.md）
4. 质量偏差 → 是否需要新原则？（→ AGENTS.md）
5. 协作摩擦 → 是否需要新边界？（→ IDENTITY.md）
6. 学习收获 → 是否需要新风格？（→ SOUL.md）
    ↓
判断：值得记住吗？
    ├── 是 → 写入对应文件 + 更新版本号 + git commit
    └── 否 → 仅保留事件记录
```

### 5.3 自我更新的边界

| 允许 | 禁止 |
|------|------|
| ✅ 新增 If-Then 规则 | ❌ 删除已有原则（需用户审批）|
| ✅ 新增工具/命令 | ❌ 修改安全红线 |
| ✅ 细化风格描述 | ❌ 改变核心身份 |
| ✅ 补充职责映射 | ❌ 扩大禁止边界 |

## 六、实施计划

### Phase 1：补全章节（立即）

为每个 agent 的 5 个文件补全缺失章节：
- IDENTITY.md：补"任务前自查清单" + "自我更新触发条件"
- SOUL.md：补"自我更新触发条件"
- MEMORY.md：补"记忆修改流程" + "记忆晋升规则"
- TOOLS.md：补"工具新增/废弃流程"
- AGENTS.md：补"原则修改流程"

### Phase 2：统一模板（1 周内）

- 用 manager maintainer sync 同步模板到各 agent
- 确保 10 个 agent 的章节结构一致

### Phase 3：验证机制（2 周内）

- 写"自查脚本"（检查每个文件是否符合本规范）
- 加入 M3 hook 的六维度评估
- 首次运行验证
